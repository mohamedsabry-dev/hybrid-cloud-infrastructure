## 1. LOCAL RUNNER SETUP
================================================================================

    Setup Local runner with tags: mac-mini, production

    Why:
        - Future on-premises infrastructure deployment needs local access
        - Mac mini will connect to internal environment via pfSense virtual IP
        - Self-hosted runner avoids GitHub-hosted runner limitations
        - Local provider mirror speeds up Terraform init (no internet download)

## 3. DAY 0 BOOTSTRAP (CloudFormation - Manual Deploy)
================================================================================

    Done via CloudFormation by AWS console admin (NOT automated)

    Why:
        - Avoid storing long-term credentials in GitHub secrets
        - Solve chicken-and-egg problem (can't use TF without state bucket)
        - Security separation: TF manages applications, NOT IAM
        - Critical security resources need human approval, not automation

    - Trust Github account with AWS
        Developer Tools > Connections
        Name: GitHub-Account
        Provider: GitHub
        Status: Available
        Arn: arn:aws:codeconnections:us-east-1:REDACTED_AWS_PROD:connection/9f7c2cde-397a-4895-8e4b-72ec6d60f3e0

    - Create Stack for fundamental Setup [Enable GitSync on main branch]

        #   Resource Type               Resource Name                                       Purpose
        1   AWS::IAM::OIDCProvider      GitHub OIDC Provider                                Identity federation for GitHub Actions
        2   AWS::S3::Bucket             hybrid-cloud-infrastructure-terraform-state         Terraform state storage
        3   AWS::DynamoDB::Table        hybrid-cloud-infrastructure-terraform-state-lock    Terraform state locking
        4   AWS::S3::Bucket             hybrid-cloud-infrastructure-audit-logs              Audit/CloudTrail logs
        5   AWS::S3::BucketPolicy       AuditBucketPolicy                                   Allow CloudTrail + Deny non-SSL

        Security Features:
        - S3 Buckets: Versioning, Encryption (AES256), Public Access Blocked
        - Terraform State Bucket: Logging to AuditBucket, Lifecycle (90 days for old versions)
        - DynamoDB: DeletionProtectionEnabled, SSESpecification enabled
        - AuditBucket: Lifecycle (365 days expiration, 90 days for old versions)
        - AuditBucketPolicy: DenyNonSSL statement (blocks non-HTTPS requests)

        Note: Resources 2, 3, 4 have DeletionPolicy: Retain - they won't be deleted if stack is deleted
        Note: OIDC thumbprint is ignored by AWS for GitHub (since July 2023) but field is required

    - Create Stack for Policies Setup [Enable GitSync on main branch]

        #   Policy Name                             Purpose
        1   HybridCloud-TerraformState-Common       S3 & DynamoDB access for Terraform state (uses !ImportValue)
        2   HybridCloud-Terraform-SecurityBoundary  PassRole for EC2-*/EKS-* only, Deny IAM mutations
        3   HybridCloud-NetworkFullManagement       Core network fabric: VPC, Subnets, Routes, VPN, Peering, NACLs, Endpoints
        4   HybridCloud-ApplicationFullManagement   App-facing: EC2, EKS, ECR, SG, NAT, ELB, EIP, ENI
        5   HybridCloud-SecurityAuditControl        CloudTrail, CloudWatch, EventBridge, SNS, Audit Bucket config

        Policy Details:
        - TerraformStatePolicy: Uses !ImportValue for bucket/table ARNs (cross-stack reference)
        - SecurityBoundary: PassRole limited to EC2-* and EKS-* role patterns only
        - NetworkFullManagement: Core fabric only (VPC, subnets, routes, VPN, peering)
        - ApplicationFullManagement: Includes SG, NAT, ELB, EIP, ENI (app-facing resources)
        - SecurityAuditControl: PassRole for CloudTrail role, manages audit infrastructure

    - Create Stack for Assume Roles by Github [Enable GitSync on main branch]

        #   Role Name                   Purpose                                 Attached Policies
        1   GitHubActions-Network       The Infrastructure Architect            TerraformState, NetworkFullManagement, ReadOnlyAccess
        2   GitHubActions-Application   The Builder                             TerraformState, SecurityBoundary, ApplicationFullManagement, ReadOnlyAccess
        3   GitHubActions-Audit         Security, Monitoring & Observability    TerraformState, SecurityAuditControl, ReadOnlyAccess

        Role Details:
        - ReadOnly role removed (redundant - all roles have ReadOnlyAccess)
        - Network: Core network only, no PassRole needed (doesn't deploy compute)
        - Application: Has SecurityBoundary for PassRole to EC2-*/EKS-* roles
        - Audit: Added ReadOnlyAccess for consistency
        - All roles: Restricted to main + mohamedsabrydev/* branches only

## 4. GITHUB WORKFLOWS
================================================================================

    Created workflows for Terraform deployment

    #   Workflow                    Purpose                         Trigger                         Runner
    1   tf-bootstrap.yml            Terraform Apply (CloudTrail)    push + workflow_dispatch        production
    2   setup-providers.yml         Provider Mirror Setup           push + workflow_dispatch        production

    Workflow Details:

    tf-bootstrap.yml:
        - Deploys CloudTrail via Terraform
        - Uses GitHubActions-Audit role
        - Push trigger: auto-runs on feature branch (for testing)
        - workflow_dispatch: manual trigger, requires typing "deploy" to confirm
        - Path filter: only runs when workflow or terraform files change

    setup-providers.yml:
        - Downloads Terraform providers to local mirror
        - Configures ~/.terraformrc for filesystem mirror
        - One-time setup (run once to populate cache)

    Why workflow_dispatch + push:
        - Push: allows testing on feature branch before merge
        - workflow_dispatch: manual control after merge to main
        - Confirmation input: prevents accidental production deploys

## 5. TERRAFORM RESOURCES (Deployed via GitHub Actions)
================================================================================

    CloudTrail Setup (cloud/aws/bootstrap/terraform/audit/)

    #   Resource                    Name                Purpose
    1   aws_cloudtrail              hybrid-main-trail   Audit all AWS API calls across all regions

    Configuration:
        - Multi-region trail: true
        - Global service events: true
        - Log file validation: enabled
        - S3 bucket: hybrid-cloud-infrastructure-audit-logs (created by CloudFormation)
        - Event Selectors: Secrets Manager data events (GetSecretValue, PutSecretValue)

    What's Logged:
        - Management events: All API calls (CreateBucket, DeleteRole, etc.) - FREE
        - Data events: Secrets Manager access (GetSecretValue) - $0.10/100k events

## 6. SECURITY CONTROLS (CODEOWNERS + Branch Protection)
================================================================================

    After Phase 1: Bootstrap disconnected from GitSync, Policies/Roles on GitSync (main only)

    Why:
        - Bootstrap: Too critical for auto-deploy, manual control by console admin
        - Policies/Roles: GitSync on main, but PR + review required before merge
        - Branch protection: Requires PR approval before merge to main
        - CODEOWNERS: /cloud/aws/iam/ requires @mohamedsabrydev approval
        - Code review is the security gate for IAM changes

    Protected Paths (require @mohamedsabrydev approval):

    #   Path                                        Reason
    1   /cloud/aws/iam/                             IAM templates (roles, policies)
    2   /cloud/aws/bootstrap/cloudformation/        Bootstrap CloudFormation templates
    3   /cloud/aws/bootstrap/**/backend.tf          Terraform state configuration
    4   /cloud/aws/bootstrap/**/providers.tf        Provider configuration
    5   /.github/workflows/tf-bootstrap.yml         Production deployment workflow
    6   /.github/workflows/setup-providers.yml      Infrastructure workflow
    7   /.github/CODEOWNERS                         The protection file itself

    Unprotected (developers can modify freely):
        - Other workflows (test workflows)
        - Dev/staging terraform configs
        - Application code

## 7. DEPLOYMENT MODEL
================================================================================

    DURING PHASE 1 (Testing):
    ─────────────────────────
    GitSync configured on feature branch (mohamedsabrydev/infra-245-phase-1-devops-foundation)
    for testing all 3 stacks before merge to main.

    AFTER PHASE 1 (Production):
    ───────────────────────────
    Stack 1: Bootstrap (MANUAL ONLY - Disconnect GitSync)
        - OIDC Provider, S3 State Bucket, DynamoDB Lock, Audit Bucket
        - Deployment file: cloud/aws/bootstrap/cloudformation/bootstrap/deployment-file.yaml
        - Reason: Rarely changes, critical infrastructure, manual control preferred

    Stack 2: Policies (GitSync on main branch)
        - IAM Managed Policies (5 policies)
        - Deployment file: cloud/aws/iam/cloudformation/policies/deployment-file.yaml
        - Auto-deploys when PR merged to main (after review)

    Stack 3: Roles (GitSync on main branch)
        - IAM Roles for GitHub Actions (3 roles)
        - Deployment file: cloud/aws/iam/cloudformation/roles/deployment-file.yaml
        - Depends on: Policies stack (uses !ImportValue)
        - Auto-deploys when PR merged to main (after review)

    Layer 2: Infrastructure (Terraform + GitHub Actions)
        - VPCs, Subnets, EC2, EKS
        - Application services

    Security Controls:
        - Branch protection on main (require PR + review)
        - CODEOWNERS: /cloud/aws/iam/ requires @mohamedsabrydev approval
        - SecurityBoundary policy denies IAM mutations from Terraform roles
        - GitSync only triggers on merge to main (not on feature branches)
        - Bootstrap stack manually deployed by console admin only

## 10. ISSUES & LESSONS LEARNED
================================================================================

    #   Issue                                       Resolution
    1   CloudFormation resource recreation          Don't change Description/Name (immutable) - see TROUBLESHOOTING.md
    2   GitSync auto-deploy security risk           Branch protection + CODEOWNERS (review before merge)
    3   Provider download slow on runner            Created local provider mirror
    4   ReadOnly role redundant                     Deleted - all roles have ReadOnlyAccess attached
    5   PassRole too permissive (Resource: *)       Limited to EC2-* and EKS-* role patterns
    6   Network/App policy overlap                  Separated: Network=fabric, App=compute+app-facing resources
    7   S3 bucket missing SSL enforcement           Added DenyNonSSL statement to bucket policies
    8   DynamoDB missing deletion protection        Added DeletionProtectionEnabled + SSESpecification
