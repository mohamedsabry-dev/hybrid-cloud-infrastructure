================================================================================
HASHICORP VAULT - USER AND POLICY CONFIGURATION GUIDE
================================================================================

OVERVIEW
--------
This guide configures HashiCorp Vault with:
- Local user authentication (userpass method)
- Role-based access control policies
- Administrative and operator user accounts
- Principle of least privilege access


================================================================================
PREREQUISITES
================================================================================

✓ Vault cluster initialized (see 07-vault_init_guide.txt)
✓ All vault nodes unsealed
✓ Root token available
✓ Policy files prepared:
  - admin-policy.hcl
  - operator-policy.hcl


Quick Unseal Reference (if needed):
------------------------------------
SSH to vault node and run:

export VAULT_ADDR='http://127.0.0.1:8200'
 vault operator unseal <Key_1>
 vault operator unseal <Key_2>
 vault operator unseal <Key_3>

(Note: Space before command prevents history logging)


================================================================================
PHASE 1: UPLOAD POLICY FILES
================================================================================

Transfer policy files from local machine to vault server:

scp admin-policy.hcl super_ansible@vault-01:/tmp
scp operator-policy.hcl super_ansible@vault-01:/tmp


================================================================================
PHASE 2: INITIAL AUTHENTICATION
================================================================================

SSH to vault-01 and authenticate with root token:

ssh vault-01.home.lab
export VAULT_ADDR='http://127.0.0.1:8200'
vault login <ROOT_TOKEN>

Expected output: "Success! You are now authenticated."


================================================================================
PHASE 3: ENABLE LOCAL AUTHENTICATION
================================================================================

Enable the userpass authentication method:

vault auth enable userpass

This allows users to authenticate with username/password combinations.

Verify:
vault auth list

Expected output: "userpass/" in the list


================================================================================
PHASE 4: UPLOAD AND APPLY POLICIES
================================================================================

4.1 - Upload Admin Policy
---------------------------
vault policy write admin /tmp/admin-policy.hcl

Expected output: "Success! Uploaded policy: admin"


4.2 - Upload Operator Policy
------------------------------
vault policy write operator /tmp/operator-policy.hcl

Expected output: "Success! Uploaded policy: operator"


4.3 - Verify Policies
----------------------
vault policy list

Expected output:
- admin
- default
- operator
- root


================================================================================
PHASE 5: CREATE USERS
================================================================================

5.1 - Create Super Admin User (God Mode)
------------------------------------------
Purpose: Full administrative access for configuration changes and emergencies
Policy: admin (unlimited permissions)

vault write auth/userpass/users/super_ansible \
    password="<SUPER_SECURE_PASSWORD>" \
    policies="admin"

⚠️  Store this password in secure password manager!
⚠️  Use ONLY for emergencies and major configuration changes


5.2 - Create Operator Users (Safe Mode)
-----------------------------------------
Purpose: Daily operational tasks with limited permissions
Policy: operator (read/write, cannot delete secrets)

Create admin1:
vault write auth/userpass/users/admin1 \
    password="<USER_PASSWORD_1>" \
    policies="operator"

Create admin2:
vault write auth/userpass/users/admin2 \
    password="<USER_PASSWORD_2>" \
    policies="operator"

⚠️  Use these accounts for day-to-day vault operations


================================================================================
PHASE 6: VERIFY USER SETUP
================================================================================

6.1 - List All Users
---------------------
vault list auth/userpass/users

Expected output:
- admin1
- admin2
- super_ansible


6.2 - Test User Authentication
--------------------------------
Test each user login:

# Test super_ansible
vault login -method=userpass username=super_ansible

# Test admin1
vault login -method=userpass username=admin1

# Test admin2
vault login -method=userpass username=admin2

Each should return: "Success! You are now authenticated."


6.3 - Verify User Policies
----------------------------
After logging in as a user, check assigned policies:

vault token lookup

Look for "policies" field in output.

Access Control Principles:
--------------------------
✓ Use operator accounts (admin1/admin2) for routine operations
✓ Reserve super_ansible for emergency access and major changes
✓ Store root token offline - use ONLY as last resort break-glass
✓ Rotate passwords regularly
✓ Audit user actions through vault logs


================================================================================
AUTHENTICATION DESIGN DECISIONS
================================================================================

Why Local Users (userpass) Instead of LDAP/IPA?
------------------------------------------------

Advantages of Local Users:
✓ Simplicity - No external dependencies
✓ Availability - Vault accessible even if IPA/LDAP is down
✓ Security - No single sign-on (SSO) risk
✓ Isolation - Vault credentials separate from system accounts

Concerns with IPA/LDAP Integration:
✗ Dependency on IPA/LDAP availability
✗ SSO complexity - same username for both vault VM and vault application
✗ Potential security risk if system account compromised
✗ Additional configuration and maintenance overhead

Initial Consideration:
We initially considered using vault_admin1 and vault_admin2 (IPA domain users)
but decided against it due to SSO security concerns and naming conflicts with
system-level accounts.


Future Enhancement Options:
---------------------------
If LDAP integration becomes necessary:

1. Enable LDAP auth method alongside userpass:
   vault auth enable ldap

2. Create separate LDAP users specifically for vault access
   (not shared with system accounts)

3. Map LDAP groups to vault policies:
   vault write auth/ldap/groups/vault-admins policies=admin
   vault write auth/ldap/groups/vault-operators policies=operator

4. Keep local users as backup authentication method


================================================================================
CLEANUP COMMANDS
================================================================================

Delete a User (if mistakes were made):
---------------------------------------
vault delete auth/userpass/users/<username>

Example:
vault delete auth/userpass/users/vault_admin1


Update User Password:
---------------------
vault write auth/userpass/users/<username>/password password="<NEW_PASSWORD>"


Update User Policies:
---------------------
vault write auth/userpass/users/<username> policies="<policy1>,<policy2>"


Delete a Policy:
----------------
vault policy delete <policy_name>


================================================================================
REFERENCE COMMANDS
================================================================================

# List all authentication methods
vault auth list

# List all policies
vault policy list

# Read a specific policy
vault policy read admin
vault policy read operator

# List all users
vault list auth/userpass/users

# View user details
vault read auth/userpass/users/<username>

# Check current authentication token
vault token lookup

# Check vault cluster status
vault operator raft list-peers

# Revoke a user's token (force logout)
vault token revoke <token>


================================================================================
TROUBLESHOOTING
================================================================================

Issue: "Error enabling userpass auth method: path is already in use"
Solution: The userpass auth method is already enabled. Skip to policy upload.

Issue: "Permission denied" when creating users
Solution: Ensure you're logged in with root token or super_ansible account.

Issue: User can't perform certain operations
Solution: Check user's assigned policy. Operators cannot delete secrets.
          Use: vault token lookup (while logged in as that user)

Issue: Forgot which policies are assigned to a user
Solution: vault read auth/userpass/users/<username>

Issue: Need to change user from operator to admin
Solution: vault write auth/userpass/users/<username> policies="admin"


================================================================================
SECURITY BEST PRACTICES
================================================================================

✓ Never share user credentials between team members
✓ Use operator accounts for daily tasks, not admin
✓ Store passwords in secure password manager (not plain text)
✓ Enable audit logging to track user actions
✓ Regularly review and rotate credentials
✓ Remove users who no longer need access
✓ Use MFA (multi-factor authentication) for production environments
✓ Keep root token offline and use only for emergencies
✓ Document all policy changes in version control
