================================================================================
HASHICORP VAULT INITIALIZATION AND UNSEALING GUIDE
================================================================================

OVERVIEW
--------
This guide covers the initial setup of a HashiCorp Vault cluster including:
- Vault initialization (generating unseal keys and root token)
- Unsealing vault nodes
- Creating administrative users
- Security best practices for key management


⚠️  CRITICAL SECURITY WARNINGS
---------------------------------
1. Unseal keys and root token are EXTREMELY sensitive
2. If lost, your vault data becomes permanently inaccessible
3. Store them in a secure password manager or physical vault
4. NEVER commit keys/tokens to git repositories
5. After server restart, vault will be sealed again and requires unsealing


================================================================================
PHASE 1: PRE-INITIALIZATION CHECKS
================================================================================

1.1 - Verify Vault Status
---------------------------
Check if vault is running and responsive:

ansible -i ../inventory vault -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault status"


================================================================================
PHASE 2: VAULT INITIALIZATION (First Node Only)
================================================================================

2.1 - Security Recommendation
-------------------------------
⚠️  DO NOT run initialization via Ansible!

Why?
- Unseal keys and root token will appear in Ansible console logs
- Keys stored temporarily in vault server's memory
- Increased exposure risk

❌ AVOID THIS:
ansible -i ../inventory vault-01.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator init"


2.2 - Recommended Method (Direct SSH)
--------------------------------------
✅ Use direct SSH connection for maximum security:

ssh vault-01.home.lab
export VAULT_ADDR='http://127.0.0.1:8200'
vault operator init

Expected Output:
- 5 Unseal Keys (you need 3 to unseal)
- 1 Initial Root Token


2.3 - Secure Key Storage
--------------------------
IMMEDIATELY after initialization:

1. Copy all 5 unseal keys and root token
2. Store in one or more of these locations:
   ✓ Password manager (1Password, Bitwarden, LastPass, etc.)
   ✓ Hardware security module (HSM)
   ✓ Physical vault/safe
   ✓ Encrypted USB drive (offline storage)

3. For lab environments ONLY (NOT production):
   - You may temporarily store in a file added to .gitignore
   - Move to secure storage as soon as possible

⚠️  NEVER commit keys to version control!


================================================================================
PHASE 3: UNSEALING VAULT NODES
================================================================================

3.1 - Understanding the Space Trick (Command History Security)
----------------------------------------------------------------
PROBLEM:
When you type commands with sensitive data, Linux saves them in ~/.bash_history
Anyone with access to your account can see these commands later

SOLUTION:
Add a single SPACE before the command to prevent it from being saved to history

Test It First:
# Normal command (will be saved):
echo "This is visible"

# Command with leading space (will NOT be saved):
 echo "This is hidden"

# Check if it worked:
history | tail -5

Verify Your Shell Configuration:
echo $HISTCONTROL

If output is "ignorespace" or "ignoreboth" → The trick works ✅
If output is empty or other value → The trick won't work ❌


3.2 - Unseal First Node (vault-01)
------------------------------------
⚠️  Note the SPACE before each ansible command below!

Unseal with 3 different keys (threshold = 3):

 ansible -i ../inventory vault-01.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_1>"
 ansible -i ../inventory vault-01.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_2>"
 ansible -i ../inventory vault-01.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_3>"

Verify unsealed status:
 ansible -i ../inventory vault-01.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault status"

Expected: "Sealed: false"


3.3 - Unseal Remaining Cluster Nodes
--------------------------------------
Repeat the unseal process for all other vault nodes in your cluster:

For vault-02:
 ansible -i ../inventory vault-02.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_1>"
 ansible -i ../inventory vault-02.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_2>"
 ansible -i ../inventory vault-02.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_3>"

For vault-03:
 ansible -i ../inventory vault-03.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_1>"
 ansible -i ../inventory vault-03.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_2>"
 ansible -i ../inventory vault-03.home.lab -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault operator unseal <PASTE_KEY_3>"

(Continue for all nodes in your cluster)


3.4 - Verify Entire Cluster
-----------------------------
Check status of all vault nodes:

ansible -i ../inventory vault -m shell -a "export VAULT_ADDR='http://127.0.0.1:8200'; vault status"

✅ Confirm all nodes show "Sealed: false"


================================================================================
PHASE 4: POLICY AND USER SETUP
================================================================================

4.1 - Upload Admin Policy
---------------------------
Transfer the admin policy to vault server:

scp admin-policy.hcl super_ansible@vault-01:/tmp

SSH to vault-01 and apply policy:
ssh vault-01.home.lab
vault policy write admin /tmp/admin-policy.hcl


4.2 - User Strategy
---------------------
Root Token Usage:
- The initial root token should be kept in a secure, offline location
- Use ONLY for emergency break-glass scenarios
- Do NOT use for day-to-day operations

Recommended Approach:
1. Create a local admin user (super_ansible) with root privileges
   - For automation and emergency access
   - Can be used instead of root token

2. Create operational admin users (admin1, admin2)
   - For regular administration tasks
   - Assigned "operator" policy (not full root)


4.3 - Create Super Admin User (Optional)
------------------------------------------
Login with root token first:
vault login <ROOT_TOKEN>

Create super_ansible user with admin policy:
vault write auth/userpass/users/super_ansible \
    password="secure_password_here" \
    policies="admin"


4.4 - Create Operational Admin Users
--------------------------------------
Login as super_ansible (or use root token):
vault login -method=userpass username=super_ansible

Create admin1:
vault write auth/userpass/users/admin1 \
    password="strong_password_for_admin1" \
    policies="operator"

Create admin2:
vault write auth/userpass/users/admin2 \
    password="strong_password_for_admin2" \
    policies="operator"


4.5 - Verify User Access
--------------------------
Test login for each user:

vault login -method=userpass username=admin1
vault login -method=userpass username=admin2


================================================================================
SECURITY BEST PRACTICES
================================================================================

✓ Initialize vault via direct SSH, not through Ansible
✓ Store unseal keys and root token in secure offline storage
✓ Use 3+ unseal keys from different team members (production)
✓ Never commit secrets to version control
✓ Use space trick or $HISTCONTROL to prevent history logging
✓ Use operational admin accounts for daily tasks
✓ Reserve root token for emergencies only
✓ Rotate passwords regularly
✓ Enable audit logging (recommended for production)
✓ Remember: vault seals on restart - keep unseal keys accessible

================================================================================
TROUBLESHOOTING
================================================================================

Issue: Vault is sealed after server restart
Solution: This is expected behavior. Run unseal commands again.

Issue: "Permission denied" when running vault commands
Solution: Make sure you're logged in (vault login) or using correct token

Issue: Command history trick not working
Solution: Check $HISTCONTROL variable. Set it with:
          export HISTCONTROL=ignorespace

Issue: Lost unseal keys
Solution: If you still have 3+ keys, you can unseal. If all lost, data is
          unrecoverable. This is why secure backup is critical!
