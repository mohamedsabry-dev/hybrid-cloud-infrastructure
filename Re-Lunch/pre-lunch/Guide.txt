Step 1: Create the IAM User (AWS Console)
Log in to your AWS Root account and follow these steps:

Navigate to IAM: Search for "IAM" in the AWS services search bar.

Create User: Click Users > Create user.

User name: terraform-runner-sabry

Access type: Select Provide user access to the AWS Management Console (optional, but helpful for you to log in as this user later) and click Next.

Set Permissions: Choose Attach policies directly.

For now: Search for and attach PowerUserAccess.

Why? AdministratorAccess is too risky. PowerUserAccess allows you to manage almost all services but restricts you from messing with IAM itself (unless we explicitly add it later).

Review and Create: Click Create user.



#####


Step 2: Generate Programmatic Access Keys
Since Terraform will run from your Mac Mini, it needs "Programmatic Access."

Click on your new user (terraform-runner-sabry).

Go to the Security credentials tab.

Scroll down to Access keys and click Create access key.

Select Command Line Interface (CLI) as the use case.

Important: Download the .csv file. You will never see the Secret Access Key again!

Step 3: Configure your Mac Mini (The Local Runner)
You mentioned using a Local Runner on GitHub. To make this work, the runner needs to know those credentials.

Install AWS CLI: On your Mac Mini terminal:

Bash

brew install awscli
Configure Profile: Run this command:

Bash

aws configure --profile terraform-sabry
Enter your Access Key, Secret Key, and preferred region (e.g., us-east-1).

Step 4: Secure the Secrets in GitHub
Since your GitHub Action will trigger the deployment, we must store the credentials safely in the repository settings, not in the code.

Go to your GitHub Repository > Settings > Secrets and variables > Actions.

Add New repository secret:

AWS_ACCESS_KEY_ID: Paste your key.

AWS_SECRET_ACCESS_KEY: Paste your secret key.

AWS_REGION: e.g., us-east-1.
