├── Architecture Summary (CI/CD Layers)
│   │
│   ├── GitHub Layer
│   │   ├── Repository with protected branches
│   │   ├── CI/CD workflows per environment
│   │   ├── Local runner for testing
│   │   └── Terraform providers mirrored locally
│   │
│   ├── AWS Layer (per environment)
│   │   ├── S3 bucket for state storage
│   │   ├── DynamoDB table for state locking
│   │   ├── OIDC provider for GitHub authentication
│   │   ├── Bootstrap role (admin, manages foundation)
│   │   ├── Infrastructure role (PowerUser, manages resources)
│   │   └── Secrets Manager (Proxmox API tokens)
│   │
│   └── Workflow Pattern
│       ├── Dev Infrastructure: dev branch → GitHubActions-Infrastructure-dev → dev AWS → dev Proxmox
│       ├── Prod Infrastructure: prod branch → GitHubActions-Infrastructure-prod → prod AWS → prod Proxmox
│       ├── Dev Security/IAM: dev-security branch → GitHubActions-TerraformAdmin-dev → dev AWS
│       ├── Prod Security/IAM: prod-security branch → GitHubActions-TerraformAdmin-prod → prod AWS
│       ├── main branch: Clean merges only (no workflow triggers, preserves clean git history)
│       └── Complete separation maintained throughout entire stack
│
├── Key Learnings from 7 Iterations
│   │
│   ├── Iteration 1-2: Manual Setup Issues
│   │   ├── Learned: Automation must include the automation setup itself
│   │   └── Chicken-and-egg problem with Terraform managing its own state
│   │
│   ├── Iteration 3-4: CloudFormation Experiments
│   │   ├── Learned: Stack dependencies create execution ordering problems
│   │   └── GitSync for stacks adds complexity without solving core issues
│   │
│   ├── Iteration 5: Cross-Account Complexity
│   │   ├── Learned: Cross-account assume roles created unnecessary spaghetti
│   │   └── Simplification to mirrored accounts provides same isolation with less complexity
│   │
│   ├── Iteration 6: Two-Account Simplification
│   │   ├── Learned: Separate accounts with identical structure is cleaner than shared resources
│   │   └── State migration challenges when refactoring backend configuration
│   │
│   └── Final approach: Two completely independent environments mirroring each other's architecture
