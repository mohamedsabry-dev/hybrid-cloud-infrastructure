Phased Operations Plan

Phase 0: Foundation Infrastructure (Month 1)
Objective: Establish core infrastructure components and validate clustering capabilities
0.1 Base Image Preparation

Create golden Rocky Linux minimal image
Apply all system updates
Install and configure SSH server
Document baseline configuration

0.2 Core Service Deployment
Deploy in order:

pfSense (networking and firewall foundation)
FreeIPA primary + FreeIPA replica (identity management)
TrueNAS (shared storage for nested cluster)
Deploy 4 nested Proxmox servers (cluster nodes)
Create dummy test VM (connectivity validation)

0.3 Proxmox Cluster Configuration

Form 4-node Proxmox cluster
Configure shared storage via TrueNAS NFS
Validate cluster quorum and node communication
Test VM migration between cluster nodes

0.4 Backup and Recovery Validation
Proxmox Backup:

Configure Proxmox backup to external storage
Perform full backup of cluster configuration
Test restore procedure to verify backup integrity

TrueNAS Backup:

Configure TrueNAS snapshot and replication
Perform backup of NFS shares and pool configuration
Test restore of TrueNAS backup to secondary server

0.5 Disaster Recovery Testing

Simulate nested Proxmox node failure
Validate cluster failover mechanisms
Restore TrueNAS backup to alternate server
Document recovery procedures and RTO/RPO

0.6 Network Architecture
VLAN and Virtual Network Design:

Create separate VLANs for internal and external traffic
Internal network: Service-to-service communication
External network: Internet-facing services and management
Avoid flat network topology

Network Segmentation:

Internal servers: Isolated network for cluster communication
External/outer layer: Separate network interface or VLAN
Configure routing between segments for required connectivity only

0.7 Hostname Standardization
Production Environment:

Physical host: pve-prod (192.168.0.120)
Nested nodes: pve-prod-1 (192.168.0.121), pve-prod-2 (192.168.0.122), pve-prod-3 (192.168.0.123), pve-prod-4 (192.168.0.124)

Development Environment:

Physical host: pve-dev (192.168.0.220)
Nested nodes: pve-dev-1 (192.168.0.221), pve-dev-2 (192.168.0.222), pve-dev-3 (192.168.0.223), pve-dev-4 (192.168.0.224)

0.8 pfSense Advanced Configuration

NTP server configuration (time synchronization)
NAT rules for internal to external traffic
Firewall rules implementing least-privilege access
VPN server setup for remote access
VLAN configuration and inter-VLAN routing
DNS forwarding and caching

Validation: All foundation services operational, clustering validated, backups tested, network segmentation complete

Phase 1: Integration and Authentication (Month 2)
Objective: Integrate services with centralized authentication and establish hybrid cloud connectivity
1.1 VPN Integration

Deploy AWS OpenVPN server instance
Configure pfSense to establish site-to-site VPN with AWS
Validate encrypted connectivity between on-premises and cloud
Test routing between local network and AWS VPC

1.2 FreeIPA Authentication Integration
pfSense Integration:

Configure pfSense to use FreeIPA for user authentication
Enable LDAP-based authorization for VPN access
Configure DNS forwarding to FreeIPA for domain lookups

Domain Integration:

Join nested Proxmox nodes to FreeIPA domain
Enable centralized user management
Configure sudo policies via FreeIPA

1.3 Hybrid Identity (Optional)

Deploy AWS Directory Service or Active Directory
Configure FreeIPA trust relationship with AWS domain
Enable cross-domain authentication for hybrid workloads

Validation: Centralized authentication working, VPN connectivity to AWS established, domain services operational

Phase 2: Platform Services Deployment (Month 3)
Objective: Deploy container orchestration, secrets management, and automation infrastructure
2.1 Kubernetes Cluster - Production
Deploy on pve-prod cluster:

3 Kubernetes master nodes (control plane HA)
3 Kubernetes worker nodes (workload capacity)
Configure cluster networking (CNI plugin)
Deploy persistent storage integration with TrueNAS
Validate pod scheduling and service discovery

2.2 Kubernetes Cluster - Development
Deploy on pve-dev cluster:

3 Kubernetes master nodes (control plane HA)
3 Kubernetes worker nodes (workload capacity)
Mirror production cluster configuration
Separate network namespace from production
Validate cluster functionality

2.3 Vault Cluster Deployment
HashiCorp Vault for secrets management:

Deploy 3-node Vault cluster for HA
Configure storage backend
Initialize and unseal Vault
Integrate with FreeIPA for authentication
Configure Kubernetes integration for pod secrets

2.4 Automation Infrastructure (LXC Containers)
Ansible Controller:

Deploy lightweight LXC container for Ansible
Configure Ansible inventory for nested environment
Create playbooks for common operations
Integrate with FreeIPA for target host authentication

Gitea Internal:

Deploy Gitea LXC container for internal Git repository
Configure for operational workflows and documentation
Enable CI/CD hooks for automation triggers
Backup configuration and repository data

2.5 Additional Platform Services

Monitoring and observability (Prometheus, Grafana)
Log aggregation (ELK/Loki)
Service mesh (if required)
Container registry (Harbor or internal registry)

Validation: Kubernetes clusters operational, Vault managing secrets, automation platform functional

Phase 3: Application Platform Readiness (Month 4)
Objective: Platform hardening, documentation, and preparation for application workloads
3.1 Platform Hardening

Security policy enforcement
Network policies and firewalls
Certificate management automation
Compliance validation

3.2 Observability and Monitoring

Complete monitoring stack deployment
Alerting rules configuration
Dashboard creation for operations
Log retention policies

3.3 Documentation

Architecture diagrams (network, compute, storage)
Runbooks for common operations
Disaster recovery procedures
Troubleshooting guides

Validation: Platform ready for application workloads, monitoring operational, documentation complete

Phase 4: Disaster Recovery Design (Month 5)
Objective: Complete DR strategy with tested recovery procedures
4.1 DR Strategy Definition

Define RTO (Recovery Time Objective) and RPO (Recovery Point Objective)
Identify critical services and dependencies
Document failover sequences

4.2 Backup Strategy

Automated backup schedules
Offsite backup replication
Backup verification and testing
Retention policies

4.3 Failover Procedures

Documented failover steps for each service
Automated failover scripts where possible
Manual intervention requirements
Rollback procedures

4.4 DR Testing

Simulate complete environment failure
Execute recovery procedures
Measure actual RTO/RPO against targets
Document lessons learned and improvements

Validation: Complete DR plan documented and tested, recovery procedures validated

Phase 5: Application Workload Deployment (Month 6+)
Objective: Deploy real applications and learn operational patterns
5.1 Application Deployment Learning

Containerize sample applications
Deploy to Kubernetes clusters
Configure ingress and service exposure
Implement CI/CD pipelines for applications

5.2 Operational Patterns

Rolling updates and blue-green deployments
Canary releases
A/B testing
Feature flags

5.3 Scaling and Performance

Horizontal pod autoscaling
Cluster autoscaling
Performance tuning
Resource optimization

5.4 Production Operations

Incident response procedures
Change management
Capacity planning
Cost optimization

Validation: Applications running successfully, operational patterns proven, team capable of day-to-day operations

Phase X: Continuous Delivery (Ongoing)
Objective: Maintain and evolve platform based on learnings and requirements
Ongoing Activities

Regular security updates and patching
Performance monitoring and optimization
Capacity planning and scaling
New service integration
Process improvement
Technology evaluation and adoption
Documentation updates
Team training and skill development

Success Criteria: Platform stable, applications performing well, team confident in operations, continuous improvement culture established

Timeline Expectations
Phase 0 (Foundation): 4-6 weeks
Phase 1 (Integration): 2-3 weeks
Phase 2 (Platform Services): 4-6 weeks
Phase 3 (Platform Readiness): 2-3 weeks
Phase 4 (DR Design): 2-3 weeks
Phase 5 (Applications): Ongoing learning and iteration
Total estimated timeline for full platform readiness: 4-5 months
Note: These are phases of work, not calendar days. Progress depends on available time, complexity encountered, and learning curve for new technologies. The goal is steady progress with thorough validation at each phase, not rushing to completion.
