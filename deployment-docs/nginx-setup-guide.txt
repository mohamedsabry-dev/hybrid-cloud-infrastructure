# Nginx Reverse Proxy - Setup Guide (DEV)

Note: If you face issues during deployment, check the troubleshooting/ folder
for the related technology section. Most common issues have been documented there.
Relevant folders: troubleshooting/nginx/, troubleshooting/linux/

---

## Overview

This guide covers the setup of Nginx as an external reverse proxy for routing
traffic to Kubernetes services. Nginx runs on an LXC container and proxies
requests to K8s worker nodes via NodePort.

Architecture:
```
External Client (AWS/VPN)
        |
        v
   Route53 Private Zone (lab.local)
        |
        v
   VPN Tunnel (10.0.0.0/16 routed)
        |
        v
   [Nginx LXC - ex-nginx.lab.local]
   10.0.65.10 (dev) / 10.0.55.10 (prod)
        |
        v
   [K8s Workers via NodePort]
   10.0.64.10-12:30080 (dev) / 10.0.54.10-12:30080 (prod)
```

---

## Prerequisites

Before starting Nginx deployment:

### Infrastructure Ready

1. FreeIPA must be running and functional (see freeipa-initial-setup-guide.txt)
2. Nginx LXC container must be deployed on Proxmox
3. VPN tunnel must be established with 10.0.0.0/16 route configured
4. K8s cluster must be running with services exposed via NodePort

### Network Connectivity

The following must already be working:
- Route for 10.0.0.0/16 via VPN tunnel from AWS VPC
- AWS Route53 Private Zone (lab.local) associated with VPC
- DNS resolution from AWS to on-prem services

## Phase 1: Nginx LXC Setup on Proxmox

### 1.1 Deploy Nginx LXC Container

If not already deployed, create the Nginx LXC container on Proxmox.

Container Settings:
- Template: Golden LXC template
- Hostname: ex-nginx
- IP Address: 10.0.65.10/24 (dev) or 10.0.55.10/24 (prod)
- Gateway: 10.0.65.1 (dev) or 10.0.55.1 (prod)
- VLAN: 65 (dev) or 55 (prod)

### 1.2 Register Host in FreeIPA

After the LXC is created, register it in FreeIPA for domain integration.

  cd ansible/dev/

  # Add nginx host to FreeIPA
  ansible-playbook -i inventory/inventory.ini playbooks/freeipa/add_hosts_to_ipa.yml --limit nginx

  # Configure domain settings (SSSD, Kerberos)
  ansible-playbook -i inventory/inventory.ini playbooks/freeipa/domain_config.yml --limit nginx

  # Fix LXC Kerberos keyring issue
  ansible-playbook -i inventory/inventory.ini playbooks/freeipa/fix_lxc_krb5_keyring.yml --limit nginx

## Phase 2: Add DNS Records

### 2.1 FreeIPA DNS Records

DNS records for all services are managed in a single playbook with a loop.
Edit the playbook to add new services when needed.

Playbook: ansible/dev/playbooks/freeipa/add_dns_records.yml

Current records (dev):
```yaml
loop:
  - { name: "vault", ip: "10.0.62.100" }
  - { name: "k8s", ip: "10.0.61.100" }
  - { name: "nginx-test-dev", ip: "10.0.65.10" }

  - { name: "grafana-dev", ip: "10.0.65.10" }
  - { name: "prometheus-dev", ip: "10.0.65.10" }
  - { name: "loki-dev", ip: "10.0.65.10" }
  - { name: "wordpress-dev", ip: "10.0.65.10" }
```

Run the playbook:

  cd ansible/dev/

  ansible-playbook -i inventory/inventory.ini playbooks/freeipa/add_dns_records.yml

IMPORTANT: When adding a new application:
1. Add the new record to the loop in add_dns_records.yml
2. Re-run the playbook to create the DNS record
3. All service records point to the Nginx IP (reverse proxy)

## Phase 4: Configure Nginx Reverse Proxy

### 4.1 Create Configuration Template

Configuration templates are stored in: ansible/dev/playbooks/nginx/templates/

Template example (nginx-test.conf.j2):
```nginx
upstream k8s_workers {
    least_conn;
    server 10.0.64.10:30080;
    server 10.0.64.11:30080;
    server 10.0.64.12:30080;
}

server {
    listen 80;
    server_name nginx-test-dev.lab.local;

    access_log /var/log/nginx/nginx-test-dev.log main;

    location / {
        proxy_pass http://k8s_workers;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 4.2 Apply Configuration

Playbook: ansible/dev/playbooks/nginx/apply_new_config.yml

This playbook:
- Copies the template to /etc/nginx/conf.d/
- Validates Nginx configuration (nginx -t)
- Reloads Nginx service

  cd ansible/dev/

  ansible-playbook -i inventory/inventory.ini playbooks/nginx/apply_new_config.yml

### 4.3 Adding New Applications

To add a new application:

1. Create a new template file: templates/<app-name>.conf.j2
2. Update the playbook to use the new template OR create a new playbook
3. Ensure the NodePort matches the K8s service NodePort
4. Run the apply playbook

## Phase 5: AWS Route53 Private Zone Records

### 5.1 Terraform Configuration

DNS records for AWS clients are managed in Terraform.

Terraform Path: terraform/dev/aws/network/main.tf

Records are defined using a for_each loop:
```hcl
locals {
  dns_records = ["nginx-test", "nginx", "prometheus", "grafana", "loki", "wordpress"]
}

resource "aws_route53_record" "services" {
  for_each = toset(local.dns_records)

  zone_id = aws_route53_zone.private.zone_id
  name    = "${each.key}-dev"
  type    = "A"
  ttl     = 300
  records = [var.dns_ingress_ip]
}
```

Variable: terraform/dev/aws/network/variables.tf
```hcl
variable "dns_ingress_ip" {
  description = "IP address for Route53 DNS records (ingress/proxy server)"
  type        = string
  default     = "10.0.65.10"  # dev: 10.0.65.10, prod: 10.0.55.10
}
```

### 5.2 Adding New Records

To add a new application to AWS Route53:

1. Edit terraform/dev/aws/network/main.tf
2. Add the new service name to the locals.dns_records list
3. Commit and push to the dev branch

### 5.3 Automatic Workflow Trigger

GitHub Workflow: .github/workflows/dev-aws-network.yml

IMPORTANT: This workflow has NO LOCK and triggers automatically on push to dev branch
when files in terraform/dev/aws/network/** are modified.

The workflow:
- Runs Terraform plan
- Waits 3 minutes for review
- Applies changes automatically

Monitor the workflow run in GitHub Actions after pushing changes.

## Adding a New Application Checklist

When adding a new application (e.g., "myapp"):

1. [ ] Create Nginx template: ansible/dev/playbooks/nginx/templates/myapp.conf.j2
2. [ ] Update apply playbook or create new one for the template
3. [ ] Add DNS record to FreeIPA: ansible/dev/playbooks/freeipa/add_dns_records.yml
       - Add: { name: "myapp-dev", ip: "10.0.65.10" }
4. [ ] Run FreeIPA DNS playbook: ansible-playbook playbooks/freeipa/add_dns_records.yml
5. [ ] Add to AWS Route53: terraform/dev/aws/network/main.tf
       - Add "myapp" to locals.dns_records list
6. [ ] Commit and push to dev branch (triggers workflow automatically)
7. [ ] Run Nginx config playbook: ansible-playbook playbooks/nginx/apply_new_config.yml
8. [ ] Test: curl http://myapp-dev.lab.local

## Troubleshooting

| Issue | Solution |
|-------|----------|
| DNS not resolving (on-prem) | Check FreeIPA DNS records, verify SSSD is running |
| DNS not resolving (AWS) | Check Route53 private zone, verify VPC association |
| Connection timeout | Check VPN tunnel, verify 10.0/16 route exists |
| 502 Bad Gateway | Check K8s service NodePort, verify workers are running |
| Nginx config syntax error | Run nginx -t to validate, check template syntax |
