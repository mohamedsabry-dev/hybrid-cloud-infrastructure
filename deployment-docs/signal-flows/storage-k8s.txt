PVC created (references StorageClass)
  └─► kube-controller-manager detects unbound PVC
        └─► external-provisioner (inside csi-nfs-controller) calls CSI CreateVolume
              └─► csi-nfs-controller mounts NFS base path temporarily
                    ├── WARNING: must run on workers — masters have no NFS route (TS-K8S-018)
                    └─► creates subdirectory /volume1/k8s-dev/pvc-<uuid>/
                          └─► external-provisioner creates PV object automatically
                                └─► kube-controller-manager binds PV ↔ PVC → Bound ✅
                                      └─► pod scheduled to node
                                            └─► kubelet → calls csi-nfs-node on same node via unix socket
                                                  └─► csi-nfs-node executes mount on node kernel:
                                                        mount -t nfs -o <mountOptions> 10.0.40.120:/volume1/k8s-dev/pvc-<uuid>
                                                        ├── nfs-retain / nfs-delete → soft, timeo=30, retrans=3
                                                        │     correct for: WordPress, Prometheus, Grafana, Loki
                                                        │     WARNING: soft crashes databases (TS-K8S-003, TS-K8S-015)
                                                        └── nfs-database → hard, timeo=600, retrans=5, intr
                                                              correct for: MariaDB, PostgreSQL
                                                              └─► container sees NFS at mountPath → pod starts ✅

PVC deleted
  └─► pvc-protection finalizer check:
        ├── pod still mounting → deletion blocked → delete pod first
        └─► no pod mounting → PVC deleted
              ├── reclaimPolicy: Retain → PV goes Released
              │     NAS directory untouched
              │     new PVC cannot auto-bind (claimRef blocks)
              │     WARNING: Released PVs accumulate silently (TS-K8S-026)
              │     cleanup: kubectl patch pv <n> -p '{"spec":{"claimRef":null}}'
              │              kubectl delete pv <n> → delete NAS dir manually
              └── reclaimPolicy: Delete → CSI deletes NAS subdirectory automatically
                    PV object deleted ✅
                    WARNING: Delete on static PV = no CSI plugin = Failed state (TS-K8S-004)

StatefulSet storage rules:
  ├── PVC name = volumeClaimTemplate.name + "-" + statefulset-name + "-" + ordinal
  ├── replicas: 0 → NO PVC created automatically → must create manually
  ├── StatefulSet delete → pods gone, PVCs kept (must delete manually)
  └── volumeClaimTemplate immutable → must delete StatefulSet + PVC to change storageClass

CSI components:
  ├── csi-nfs-controller (Deployment, workers only) → CREATE / DELETE NAS subdirectories
  │     if down: no new provisioning, existing mounts unaffected
  └── csi-nfs-node (DaemonSet, every node) → MOUNT / UNMOUNT on node
        WARNING: csi-nfs-node restart breaks active mounts on that node (TS-K8S-015)
        fix: kubectl delete pod <csi-nfs-node-pod> → DaemonSet recreates → delete app pod
