External request arrives (browser / curl)
  └─► DNS resolves *.lab.local → external nginx LXC (10.0.65.10)
        └─► external nginx matches server_name *.lab.local
              └─► upstream k8s_workers (least_conn):
                    picks worker with fewest active connections
                    └─► forwards to worker node IP:30080
                          └─► NodePort Service (created by ingress-nginx HelmRelease)
                                type: NodePort, port: 30080
                                └─► routes to ingress-nginx controller pod on that node
                                      └─► ingress-nginx controller:
                                            watches ALL Ingress objects in cluster
                                            for each Ingress object checks:
                                              ├── ingressClassName matches my IngressClass name?
                                              │     NO  → ignore, not mine
                                              │     YES → this is mine → enforce routing rule
                                              └─► reads routing rule:
                                                    host: wordpress-dev.lab.local
                                                    path: / → backend: service wordpress port 80
                                                    └─► reads annotations:
                                                          proxy-body-size: 500m → allow large uploads
                                                          affinity: cookie → sticky session
                                                          session-cookie-name: wordpress-sticky
                                                          └─► checks sticky cookie in request:
                                                                ├── no cookie → pick a pod, set cookie
                                                                └── has cookie → route to same pod
                                                                      └─► forwards to Service ClusterIP:80
                                                                            └─► Service selector: app=wordpress
                                                                                  picks healthy pod (readiness=true)
                                                                                  └─► pod handles request ✅

IngressClass — the name tag (glue between object and controller):
  ├── HelmRelease creates: ingressClassResource.name: nginx → IngressClass object registered
  ├── Ingress object says: ingressClassName: nginx → assign me to class nginx
  └── controller sees: ingressClassName matches my registered name → I handle this

Multiple controllers pattern (if needed):
  ├── IngressClass: nginx-external → public traffic, port 30080
  ├── IngressClass: nginx-internal → internal tools, port 30081
  └── each controller only handles Ingress objects referencing its own class name

ingress-nginx components (created by HelmRelease):
  ├── controller pods (3 replicas, anti-affinity across workers)
  │     watches Ingress objects → updates nginx.conf dynamically
  │     no restart needed when Ingress rules change
  ├── NodePort Service → opens 30080/30443 on every worker node
  └── IngressClass object → registers name tag "nginx" in cluster

annotations on Ingress object:
  ├── NOT a webhook → read directly by ingress-nginx controller
  ├── nginx.ingress.kubernetes.io/proxy-body-size → client_max_body_size in nginx.conf
  ├── nginx.ingress.kubernetes.io/affinity: cookie → sticky session configuration
  └── nginx.ingress.kubernetes.io/session-cookie-* → cookie name, expiry settings
