================================================================================
ISSUE #2: NVME DETECTION ERROR LOOP
================================================================================

SYMPTOM:
--------
Screen filled with repeating error messages:
"ata3.00: ATA: Correctable error message received from 0000:01:00.0"
Loop repeated indefinitely, system unable to proceed

ERROR ANALYSIS:
---------------
PCI Address: 0000:01:00.0 (NVMe controller)
Error Type: Correctable errors (hardware communication issue)
Timing: During hardware enumeration (/dev population phase)
Pattern: Continuous retry loop attempting NVMe initialization

ROOT CAUSE:
-----------
NVMe power management and device initialization conflict
Likely causes:
1. APST (Autonomous Power State Transition) incompatibility
2. Power management settings causing detection failures
3. Driver initialization timing issues with NVMe controller

TROUBLESHOOTING PROCESS:
------------------------

### Attempt 1: NVMe Power Management Disable
Action: Added boot parameter to disable NVMe power states
Process:
   1. Reboot from USB
   2. At Proxmox boot menu, highlight "Install Proxmox VE (Graphical)"
   3. Press 'e' to edit boot parameters
   4. Navigate to end of 'linux' line
   5. Added parameter: nvme_core.default_ps_max_latency_us=0
   6. Pressed Ctrl+X to boot

Expected: Disable NVMe APST, allow clean detection
Result: FAILED - Still stuck at /dev population

### Attempt 2: Multiple Aggressive Parameters
Action: Added comprehensive workaround parameters
Parameters tested:
   - nvme_core.default_ps_max_latency_us=0 pci=nomsi libata.force=noncq acpi=off
   - nomodeset acpi=off pci=nomsi

Result: FAILED - Still unable to proceed past /dev stage

### Attempt 3: BIOS Configuration Check
Action: Verified BIOS settings
Checked:
   - SATA Mode: Already set to AHCI (correct)
   - Secure Boot: Already disabled (correct)
   - Boot Mode: UEFI (correct)
   - NVMe detected in BIOS: YES (1.8TB visible)

Result: BIOS settings correct, not a BIOS configuration issue

================================================================================
ISSUE #3: GRAPHICS DRIVER CONFLICT (ACTUAL ROOT CAUSE)
================================================================================

DISCOVERY:
----------
Reference found: O'Reilly Mastering Proxmox guide
URL: https://www.oreilly.com/library/view/mastering-proxmox/9781788397605/
Section: Installation troubleshooting - NVIDIA graphics conflict

ROOT CAUSE IDENTIFIED:
----------------------
NVIDIA graphics drivers attempting to initialize during boot
Conflict with NVMe detection process causing system hang
Graphics driver probe interfering with storage controller initialization

SOLUTION: NOMODESET BOOT PARAMETER
-----------------------------------

What nomodeset does:
- Disables kernel mode setting (KMS) for graphics
- Prevents graphics drivers from loading during boot
- Allows system to use basic framebuffer instead
- Eliminates driver conflicts during hardware detection

RESOLUTION PROCESS:
-------------------

Step 1: Reboot from USB (again)

Step 2: At Proxmox boot menu
   - Highlight "Install Proxmox VE (Graphical)"
   - Press 'e' to edit boot parameters

Step 3: Add nomodeset parameter
   Location: End of the 'linux' line (after 'quiet')
   Parameter added: nomodeset
   
   Full line example:
   linux /boot/linux26 ro ramdisk_size=16777216 rw quiet splash=silent nomodeset

Step 4: Boot with new parameter
   - Pressed Ctrl+X to boot
   - System bypassed graphics driver initialization
   - Hardware detection completed successfully

================================================================================
LESSONS LEARNED & KEY TAKEAWAYS
================================================================================

1. GRAPHICS DRIVER CONFLICTS ARE COMMON
   - nomodeset parameter is critical for many systems
   - NVIDIA drivers particularly problematic during install
   - Should be first troubleshooting step for boot hangs

2. USB ISSUES ARE OFTEN RED HERRINGS
   - Changed USB media multiple times (not the issue)
   - Boot method and parameters more important than media
   - Don't waste time recreating USB without investigating boot logs

3. NVME POWER MANAGEMENT PARAMETERS
   - Often suggested but not always the solution
   - nvme_core.default_ps_max_latency_us=0 didn't help in this case
   - Graphics conflict masked as storage issue

4. SEPARATE PHYSICAL DRIVES = CLEAN DUAL-BOOT
   - 1.8TB NVMe for Proxmox
   - Separate SATA for Windows
   - No partitioning complexity
   - Zero risk to existing OS
   - Boot selection via BIOS

5. DOCUMENTATION IS CRITICAL
   - O'Reilly guide provided actual solution
   - Community documentation more valuable than official docs
   - Real-world troubleshooting scenarios essential

BOOT PARAMETERS REFERENCE
================================================================================

Parameter: nomodeset
Purpose: Disable kernel mode setting (graphics drivers)
Use Case: Graphics card conflicts (NVIDIA especially)
Success Rate: High for boot hangs

Parameter: nvme_core.default_ps_max_latency_us=0
Purpose: Disable NVMe power state transitions
Use Case: NVMe detection/enumeration failures
Success Rate: Medium, hardware-dependent

Parameter: pci=nomsi
Purpose: Disable MSI (Message Signaled Interrupts)
Use Case: PCI device detection issues
Success Rate: Low, very specific hardware issues

Parameter: acpi=off
Purpose: Disable ACPI (Advanced Configuration and Power Interface)
Use Case: Power management conflicts
Warning: Disables power management entirely
Success Rate: Low, last resort option

Parameter: libata.force=noncq
Purpose: Disable Native Command Queuing for SATA
Use Case: SATA drive detection issues
Success Rate: Low for NVMe systems

How to Add Boot Parameters:
1. At Proxmox boot menu, press 'e'
2. Find line starting with 'linux'
3. Go to end of line (after 'quiet')
4. Add parameter (space-separated)
5. Press Ctrl+X or F10 to boot
