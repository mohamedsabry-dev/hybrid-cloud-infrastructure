ISSUE 1: LAPTOP SUSPENDS WHEN MONITOR TURNS OFF
================================================================================

SYMPTOM:
--------
- Proxmox becomes inaccessible when laptop screen turns off
- System appears to suspend/sleep
- Cannot connect to web UI when lid closed or screen blanked

ROOT CAUSE:
-----------
Default power management settings suspend system on lid close or screen timeout

SOLUTION:
---------

Step 1: Edit systemd logind configuration
   Command: nano /etc/systemd/logind.conf

Step 2: Find and modify these lines:
   CHANGE FROM:
      #HandleLidSwitch=suspend
      #HandleLidSwitchExternalPower=suspend
      #HandleLidSwitchDocked=ignore
   
   CHANGE TO:
      HandleLidSwitch=ignore
      HandleLidSwitchExternalPower=ignore
      HandleLidSwitchDocked=ignore
   
   (Remove # and change suspend to ignore)

Step 3: Save file
   In nano: Ctrl+O (save), Ctrl+X (exit)

Step 4: Restart service
   Command: systemctl restart systemd-logind

Step 5: Verify changes
   Command: cat /etc/systemd/logind.conf | grep HandleLid
   
   Should show:
      HandleLidSwitch=ignore
      HandleLidSwitchExternalPower=ignore
      HandleLidSwitchDocked=ignore

RESULT:
-------
✓ Laptop will not suspend when lid closes
✓ Screen can turn off without affecting Proxmox
✓ System remains accessible via network

OPTIONAL: Disable all sleep/suspend modes
   Command: systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target

ISSUE 2: CHROME CANNOT ACCESS PROXMOX (ERR_ADDRESS_UNREACHABLE)
================================================================================

SYMPTOM:
--------
- Safari can access Proxmox web UI at https://192.168.0.110:8006
- Chrome shows: "This site can't be reached" or "ERR_ADDRESS_UNREACHABLE"
- Incognito mode doesn't help

ROOT CAUSE:
-----------
Chrome has stricter SSL certificate validation than Safari
Self-signed Proxmox certificate doesn't meet Chrome's security requirements

ATTEMPTED FIXES (DIDN'T WORK):
-------------------------------
❌ Clear Chrome cache
❌ Clear SSL state (chrome://net-internals)
❌ Incognito mode
❌ Typing 'thisisunsafe' on error page

SOLUTION:
---------

OPTION 1: Use Safari (Recommended - Immediate)
   - Safari works perfectly with self-signed certificates
   - Full Proxmox functionality available
   - No configuration needed
   - Use Safari for all Proxmox management

OPTION 2: Fix Certificate Later (Recommended - Long-term)
   - Deploy pfSense (Phase 2)
   - Install Let's Encrypt certificate
   - Chrome will work with proper certificate
   - Better security overall

OPTION 3: Force Chrome to Accept (Not Recommended)
   - Requires adding certificate to macOS keychain
   - Requires trusting self-signed cert system-wide
   - Security risk
   - Time-consuming
   - Not worth it for temporary setup

WORKAROUND:
-----------
Use Safari for Proxmox web UI
Use Chrome for everything else (GitHub, AWS, documentation)

RESULT:
-------
✓ Full Proxmox access via Safari
✓ No functionality lost
✓ Chrome works for other sites
✓ Will be resolved after proper certificate installed

PERMANENT FIX (Phase 2+):
--------------------------
After pfSense deployment:
1. Install Let's Encrypt certificate on Proxmox
2. Configure proper DNS
3. Chrome will work without issues

Commands for Let's Encrypt (future reference):
   apt install python3-certbot-nginx
   certbot --nginx -d pve.lab.local

ISSUE 3: APT UPDATE FAILS WITH 401 UNAUTHORIZED
================================================================================

SYMPTOM:
--------
- Running "apt update" shows 401 Unauthorized error
- Error message: "Failed to fetch https://enterprise.proxmox.com/debian/pve/..."
- Repository is not signed warning

ROOT CAUSE:
-----------
Proxmox enterprise repositories are enabled by default but require paid subscription

SOLUTION:
---------

Step 1: Disable enterprise repositories
   mv /etc/apt/sources.list.d/ceph.sources /etc/apt/sources.list.d/ceph.sources.disabled
   mv /etc/apt/sources.list.d/pve-enterprise.list /etc/apt/sources.list.d/pve-enterprise.list.disabled
   mv /etc/apt/sources.list.d/pve-enterprise.sources /etc/apt/sources.list.d/pve-enterprise.sources.disabled

Step 2: Verify no-subscription repo exists
   cat /etc/apt/sources.list.d/pve-install-repo.list

   For Proxmox 8.x (Debian Bookworm):
   deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription

   For Proxmox 9.x (Debian Trixie):
   deb http://download.proxmox.com/debian/pve trixie pve-no-subscription

Step 3: If no-subscription repo missing or wrong version, create/fix it
   Proxmox 8.x:
   echo "deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription" > /etc/apt/sources.list.d/pve-no-subscription.list

   Proxmox 9.x:
   echo "deb http://download.proxmox.com/debian/pve trixie pve-no-subscription" > /etc/apt/sources.list.d/pve-install-repo.list

Step 4: Update package lists
   apt update

RESULT:
-------
✓ apt update completes without errors
✓ Can install/upgrade packages
✓ No subscription required

ISSUE 4: WARNING "OLD SUITE 'BOOKWORM' CONFIGURED" (PROXMOX 9.x)
================================================================================

SYMPTOM:
--------
- Warning in APT repositories: "old suite 'bookworm' configured!"
- Yellow warning icon next to repository in web UI

ROOT CAUSE:
-----------
Proxmox 9.x uses Debian Trixie but repository is configured for Bookworm

SOLUTION:
---------

Update the no-subscription repository to use trixie:
   echo "deb http://download.proxmox.com/debian/pve trixie pve-no-subscription" > /etc/apt/sources.list.d/pve-install-repo.list
   apt update

RESULT:
-------
✓ Warning disappears
✓ Repository matches Proxmox version

ISSUE 5: PKGUPDATES FILE MISSING ERROR
================================================================================

SYMPTOM:
--------
- Error in logs: "can't open '/var/lib/pve-manager/pkgupdates' - No such file or directory"

ROOT CAUSE:
-----------
File is created on first package update check, doesn't exist on fresh install

SOLUTION:
---------

Simply run apt update:
   apt update

Or click "Refresh" in Proxmox web UI under Updates section.

RESULT:
-------
✓ File gets created automatically
✓ Error disappears

ISSUE 6: SUBSCRIPTION NAG POPUP IN WEB UI
================================================================================

SYMPTOM:
--------
- Popup appears on login: "No valid subscription"
- Annoying for home lab use

ROOT CAUSE:
-----------
Proxmox shows subscription reminder for users without paid subscription

SOLUTION:
---------

Step 1: Remove the subscription nag
   sed -Ezi.bak "s/(Ext\.Msg\.show\(\{\s+title: gettext\('No valid sub)/void\(\{ \/\/\1/g" /usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js

Step 2: Restart web service
   systemctl restart pveproxy

Step 3: Clear browser cache and refresh

NOTE: This patch needs to be reapplied after Proxmox updates.

RESULT:
-------
✓ No more subscription popup on login
✓ Full functionality retained
