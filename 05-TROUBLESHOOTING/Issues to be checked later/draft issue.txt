Let me give you practical solutions:
Problem Summary

ESXi autostart is host-local (doesn't transfer to DR host)
vApp doesn't help when production host is down (cluster-level, needs both hosts)
DR host boots up cold, doesn't know startup order

Solution 1: Startup Script on DR Host (Recommended for your setup)
Create a script that runs on DR ESXi boot:
bash# SSH to DR ESXi host
# Create /etc/rc.local.d/local.sh

cat > /etc/rc.local.d/local.sh << 'EOF'
#!/bin/sh

# Wait for ESXi services to fully start
sleep 60

# Startup sequence (adjust VM names and delays)
vim-cmd vmsvc/power.on $(vim-cmd vmsvc/getallvms | grep "DC01" | awk '{print $1}')
sleep 120  # Wait for DC to boot

vim-cmd vmsvc/power.on $(vim-cmd vmsvc/getallvms | grep "DNS01" | awk '{print $1}')
sleep 60

vim-cmd vmsvc/power.on $(vim-cmd vmsvc/getallvms | grep "vCenter" | awk '{print $1}')
sleep 180  # Wait for vCenter

# Add remaining VMs...
EOF

chmod +x /etc/rc.local.d/local.sh
/sbin/auto-backup.sh  # Persist across reboots
Pros:

✅ Works when DR host boots standalone
✅ Simple, no cluster dependency
✅ Exact startup order control

Cons:

❌ Needs manual sync when startup order changes
❌ Lost on ESXi reinstall (backup the script)

Solution 2: PowerCLI Script on Separate Management VM
Have a lightweight Linux/Windows VM that auto-starts first and orchestrates:
powershell# Runs on management VM (auto-starts on DR host)
# C:\Scripts\DR-Startup.ps1

Connect-VIServer -Server DR-ESXI-IP -User root -Password XXX

# Startup sequence
Start-VM -VM "DC01" -Confirm:$false
Start-Sleep 120

Start-VM -VM "DNS01" -Confirm:$false  
Start-Sleep 60

Start-VM -VM "vCenter" -Confirm:$false
Start-Sleep 180

# Remaining VMs...
Set this VM to autostart on DR ESXi, then it handles the rest.
