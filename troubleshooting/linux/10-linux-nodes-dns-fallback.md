# TS-LNX-010 | 2026-04-15 | IN PROGRESS

## 1. Context
- System: Linux Node DNS Configuration / NetworkManager / FreeIPA Client
- Environment: DEV (lab.local)
- Related components: Vault cluster, Local runner, All FreeIPA-enrolled nodes
- Discovery: **Discovered during IPA Domain Down DR Test (Part 2)**

---

## 2. Issue

Linux nodes enrolled in FreeIPA have no DNS fallback configured. When IPA DNS (10.0.60.10) is down:
- External DNS resolution fails completely
- AWS KMS endpoints unreachable (Vault auto-unseal fails on restart)
- GitHub unreachable (Local runner disconnects)
- Any service needing external DNS fails

### Affected Nodes
| Node Type | Nodes | Critical Service at Risk |
|-----------|-------|-------------------------|
| Vault cluster | vault1, vault2, vault3 | AWS KMS auto-unseal |
| Local runner | local-runner | GitHub Actions connectivity |
| K8s nodes | k8s-master1/2/3, k8s-worker1/2/3 | Node-level external DNS |

## 4. Root Cause Analysis

### 4.1 Why Manual DNS Is Ignored

```
NetworkManager Config:
  ipv4.dns:              8.8.8.8,1.1.1.1    ← Manual fallback DNS
  ipv4.ignore-auto-dns:  no                  ← Accepts auto-discovered DNS
  ipv4.dns-priority:     0                   ← Default priority

FreeIPA Client Enrollment:
  → Pushes nameserver 10.0.60.10 via auto-config
  → Auto DNS REPLACES manual DNS (not appends)

Result in /etc/resolv.conf:
  nameserver 10.0.60.10   ← Only FreeIPA, fallback ignored!
```

### 4.2 Risk Matrix

| Scenario | Impact | Severity |
|----------|--------|----------|
| IPA down + Vault running | No impact (already unsealed) | LOW |
| IPA down + Vault restart | **Vault stays SEALED** (KMS unreachable) | **CRITICAL** |
| IPA down + Local runner | GitHub Actions disconnects | HIGH |
| IPA down + K8s nodes | External DNS fails at node level | MEDIUM |

## 6. Solution Options

### Option A: Priority-Based (Recommended)
Keep auto-dns but prioritize manual settings:
```bash
nmcli con mod <connection> ipv4.dns-priority -10
nmcli con mod <connection> ipv4.dns "10.0.60.10,8.8.8.8,1.1.1.1"
nmcli con up <connection>
```

### Option B: Ignore Auto-DNS
Disable auto-discovered DNS, use only manual:
```bash
nmcli con mod <connection> ipv4.ignore-auto-dns yes
nmcli con mod <connection> ipv4.dns "10.0.60.10,8.8.8.8,1.1.1.1"
nmcli con up <connection>
```

### Option C: Terraform/Cloud-Init
Fix at provisioning level in VM templates.

### Expected Result
```
# /etc/resolv.conf after fix
search lab.local
nameserver 10.0.60.10
nameserver 8.8.8.8
nameserver 1.1.1.1
```
