[Issue Description]
Ansible playbook `k8s_hosts_fallback.yml` adds entries to /etc/hosts, but cloud-init
overwrites them on reboot. The /etc/hosts file is regenerated from template on every boot.

Impact:
  - /etc/hosts fallback entries lost after reboot
  - Node-level hostname resolution fails when IPA is down (after reboot)
  - Ansible-managed block disappears

Note: This is LOW priority because:
  - K8s nodes communicate via IP internally (kubelet, etcd, API)
  - Pod DNS uses CoreDNS (fixed separately in TS-K8S-033)
  - /etc/hosts mainly needed for SSH by hostname during IPA outage

# Root Cause

Cloud-init config has `manage_etc_hosts: True` which regenerates /etc/hosts from
template on every boot:

Template file: `/etc/cloud/templates/hosts.redhat.tmpl`

```jinja
## template:jinja
{#
This file /etc/cloud/templates/hosts.redhat.tmpl is only utilized
if enabled in cloud-config.  Specifically, in order to enable it
you need to add the following to config:
  manage_etc_hosts: True
-#}
# Your system has configured 'manage_etc_hosts' as True.
...
127.0.0.1 {{fqdn}} {{hostname}}
127.0.0.1 localhost.localdomain localhost
...
```


# Verified: DNS Fallback Still Works

```
[k8s_admin@k8s-master1 ~]$ cat /etc/resolv.conf
# Generated by NetworkManager
search lab.local
nameserver 10.0.60.10
nameserver 8.8.8.8
```

The zzz-ipa.conf DNS fallback (TS-LNX-003) survives reboot because it's managed by
NetworkManager, not cloud-init.

_____________________________________________________________________

[Suspected Root Cause]
Cloud-init owns /etc/hosts with `manage_etc_hosts: True`. On every boot, cloud-init
regenerates the file from `/etc/cloud/templates/hosts.redhat.tmpl`, wiping any
changes made by Ansible.

_____________________________________________________________________

[Potential Solutions]

Option A: Disable cloud-init /etc/hosts management
  - Set `manage_etc_hosts: False` in cloud-config
  - Pros: Ansible changes persist
  - Cons: Lose cloud-init hostname management

Option B: Modify the cloud-init template
  - Add static entries to `/etc/cloud/templates/hosts.redhat.tmpl`
  - Pros: Survives reboot, cloud-init friendly
  - Cons: Template is per-node, harder to manage centrally

Option C: Fix at Terraform/Proxmox provisioning level
  - Add entries via cloud-init user-data during VM creation
  - Pros: Proper Infrastructure-as-Code approach
  - Cons: Requires Terraform changes, re-provisioning

Option D: Accept current behavior (Recommended for now)
  - K8s nodes work via IP anyway
  - Pod DNS fixed via CoreDNS hosts plugin (TS-K8S-033)
  - Run playbook after reboots if needed
  - Pros: No changes needed
  - Cons: Manual step after reboot
