[Issue Description]
Discovered during IPA Domain Down DR Test (Part 2).
Linux nodes enrolled in FreeIPA have no DNS fallback configured. When IPA DNS
(10.0.60.10) is down, external DNS resolution fails completely.

Impact when IPA is down:
  - AWS KMS endpoints unreachable → Vault auto-unseal fails on restart (CRITICAL)
  - GitHub unreachable → Local runner disconnects (HIGH)
  - Any service needing external DNS fails (MEDIUM)

_____________________________________________________________________

[Analysis]

# Initial Check Notes:
Checked resolv.conf on vault nodes and local-runner.

Command:
  cat /etc/resolv.conf  (on vault1)

Output:
  # Generated by NetworkManager
  search lab.local
  nameserver 10.0.60.10
  (only FreeIPA — no fallback)

Confirmed internal DNS works but external fails:

Command:
  ping vault2.lab.local   → works (via /etc/hosts fallback)
  ping google.com         → hangs (no external DNS)

Vault cluster internal communication confirmed safe — Raft peers use IPs,
HA cluster address uses IP, /etc/hosts has vault1/2/3 entries.
Risk is specifically external DNS (AWS KMS endpoints for auto-unseal).

Checked local-runner NetworkManager config:

Command:
  nmcli connection show eth0 | grep dns

Output:
  ipv4.dns:              8.8.8.8,1.1.1.1   ← manual fallback configured
  ipv4.ignore-auto-dns:  no                ← PROBLEM — accepts auto-discovered DNS

FreeIPA client enrollment pushes nameserver 10.0.60.10 via auto-config.
Because ignore-auto-dns is no, auto-discovered DNS replaces the manual entries
instead of appending to them. resolv.conf ends up with only 10.0.60.10.

Confirmed manual DNS works when specified directly:

Command:
  nslookup google.com 8.8.8.8

Output:
  Valid response — 8.8.8.8 is reachable, just not in resolv.conf.


# Suspected Root Cause
FreeIPA client enrollment pushes nameserver 10.0.60.10 via NetworkManager
auto-config. With ipv4.ignore-auto-dns: no, auto-discovered DNS overwrites
manual DNS entries instead of merging with them. resolv.conf ends up with only
the FreeIPA nameserver — no fallback when IPA is down.


# More Checks Notes:
Risk assessment across node types:

  IPA down + Vault running      → no impact (already unsealed)         LOW
  IPA down + Vault restart      → Vault stays SEALED, KMS unreachable  CRITICAL
  IPA down + Local runner       → GitHub Actions disconnects            HIGH
  IPA down + K8s nodes          → external DNS fails at node level      MEDIUM

Vault cluster safety check:
  Raft peer addresses   → 10.0.62.10/11/12:8201  IP-based, safe
  HA cluster address    → https://10.0.62.10:8201 IP-based, safe
  /etc/hosts fallback   → vault1/2/3 entries present, safe
  AWS KMS auto-unseal   → kms.*.amazonaws.com     needs external DNS, AT RISK


# Suspected Solution
Option A (recommended): Set ipv4.dns-priority to negative value so manual DNS
takes precedence over auto-discovered DNS, include FreeIPA + fallbacks together.

Option B: Set ipv4.ignore-auto-dns yes and manage DNS entries manually.

Option C: Fix at provisioning level in Terraform/cloud-init templates.

Expected resolv.conf after fix:
  nameserver 10.0.60.10
  nameserver 8.8.8.8
  nameserver 1.1.1.1

[Final Root Cause]
FreeIPA client enrollment pushes nameserver 10.0.60.10 via NetworkManager
auto-config. ipv4.ignore-auto-dns is no by default, so auto-discovered DNS
overwrites manual fallback entries. resolv.conf contains only 10.0.60.10.
When FreeIPA is down, all external DNS resolution fails — including AWS KMS
endpoints needed for Vault auto-unseal on restart.

[Final Solution]
Not fully applied yet. Planned in phases:

Phase 1 — Test on local-runner:
  nmcli con mod eth0 ipv4.dns-priority -10
  nmcli con mod eth0 ipv4.dns "10.0.60.10,8.8.8.8,1.1.1.1"
  nmcli con up eth0
  cat /etc/resolv.conf  # verify all three nameservers present

Phase 2 — Apply to Vault nodes (highest priority, CRITICAL risk):
  nmcli con mod <connection> ipv4.dns-priority -10
  nmcli con mod <connection> ipv4.dns "10.0.60.10,8.8.8.8,1.1.1.1"
  nmcli con up <connection>

Phase 3 — Apply to all nodes via Ansible playbook.

Phase 4 — Update Terraform/cloud-init so new VMs get fallback DNS at provisioning.
