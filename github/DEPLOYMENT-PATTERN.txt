================================================================================
                         DEPLOYMENT WORKFLOW PATTERN
================================================================================

How code flows from development to production.

================================================================================
                         STANDARD CHANGES (NO IAM)
================================================================================

Path: dev → prod → main
Use for: Proxmox VMs, LXCs, infrastructure changes (no IAM/security)

Flow Diagram
─────────────────────────────────────────────────────────────────────────────────

    ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
    │  dev    │────▶│  Test   │────▶│  prod   │────▶│  main   │
    │ (push)  │     │  Pass   │     │  (PR)   │     │  (PR)   │
    └─────────┘     └─────────┘     └─────────┘     └─────────┘
         │                              │               │
         ▼                              ▼               ▼
    Infrastructure-dev            Infrastructure-prod   Milestone
    workflow runs                 workflow runs         complete

Steps
─────────────────────────────────────────────────────────────────────────────────
1. Push changes to dev branch
2. Infrastructure-dev workflow runs automatically
3. Test and verify in DEV environment
4. Create PR from dev → prod (requires review & approval)
5. Merge PR → Infrastructure-prod workflow runs
6. Test and verify in PROD environment
7. When phase/milestone complete: PR from prod → main

================================================================================
                         IAM/SECURITY CHANGES
================================================================================

Path: dev → dev-security → prod-security → prod → main
Use for: IAM roles, policies, permissions, security configurations

Flow Diagram
─────────────────────────────────────────────────────────────────────────────────

    ┌─────────┐     ┌──────────────┐     ┌───────────────┐     ┌─────────┐
    │  dev    │────▶│ dev-security │────▶│ prod-security │────▶│  prod   │
    │ (push)  │     │    (PR)      │     │     (PR)      │     │  (PR)   │
    └─────────┘     └──────────────┘     └───────────────┘     └─────────┘
                          │                    │                    │
                          ▼                    ▼                    ▼
                    TerraformAdmin-dev   TerraformAdmin-prod   Infrastructure-prod
                    workflow runs        workflow runs         workflow runs

Steps
─────────────────────────────────────────────────────────────────────────────────
1. Push changes to dev branch (test infrastructure first)
2. Create PR from dev → dev-security (requires review)
3. Merge PR → TerraformAdmin-dev workflow runs (IAM changes in DEV AWS)
4. Test and verify IAM/security in DEV environment
5. Create PR from dev-security → prod-security (requires review)
6. Merge PR → TerraformAdmin-prod workflow runs (IAM changes in PROD AWS)
7. Create PR from prod-security → prod (infrastructure deployment if needed)
8. When phase/milestone complete: PR from prod → main

================================================================================
                         PATH SUMMARY
================================================================================

Change Type        │ Branch Path
───────────────────┼─────────────────────────────────────────────────────────────
Infrastructure     │ dev → prod → main
IAM/Security       │ dev → dev-security → prod-security → prod → main

================================================================================
                         PR REQUIREMENTS
================================================================================

PR Requirements by Target Branch
─────────────────────────────────────────────────────────────────────────────────
Target Branch     │ Review Required │ CI Checks │ Who Can Merge
──────────────────┼─────────────────┼───────────┼─────────────────────────────
main              │ Yes (1+)        │ Required  │ CODEOWNERS
prod              │ Yes (1+)        │ Required  │ CODEOWNERS
prod-security     │ Yes (1+)        │ -         │ CODEOWNERS
dev-security      │ Yes (1+)        │ -         │ CODEOWNERS
dev               │ No              │ -         │ Anyone

================================================================================
                         EXAMPLE: ADDING A NEW VM
================================================================================

Scenario: Add a new LXC container to DEV environment

1. Create/edit terraform config:
   terraform/dev/proxmox/lxc/new-container/main.tf

2. Push to dev:
   git add .
   git commit -m "Add new-container LXC to DEV"
   git push origin dev

3. Workflow runs:
   - Infrastructure-dev workflow triggered
   - OIDC auth to AWS DEV account
   - Terraform creates LXC

4. Test in DEV:
   - SSH to container
   - Verify configuration
   - Run integration tests

5. PR to prod:
   - Create PR: dev → prod
   - Add description of changes
   - Request review

6. After approval:
   - Merge PR
   - Infrastructure-prod workflow runs
   - LXC created in PROD

7. When milestone complete:
   - Create PR: prod → main
   - Merge to preserve in main branch

================================================================================
                         EXAMPLE: ADDING A NEW IAM ROLE
================================================================================

Scenario: Add new IAM role for a service

1. Create terraform config:
   terraform/dev/aws/iam/new-role/main.tf

2. Push to dev (test structure):
   git push origin dev

3. PR to dev-security:
   - Create PR: dev → dev-security
   - Request review (IAM changes are sensitive)

4. After approval & merge:
   - TerraformAdmin-dev workflow runs
   - IAM role created in DEV AWS

5. Test in DEV:
   - Verify role permissions
   - Test role assumption

6. PR to prod-security:
   - Create PR: dev-security → prod-security
   - Request review

7. After approval & merge:
   - TerraformAdmin-prod workflow runs
   - IAM role created in PROD AWS

8. Continue through prod → main

================================================================================
                         HOTFIX PROCESS
================================================================================

For urgent production fixes:

1. Create fix on dev branch
2. Test in DEV environment
3. Create PR: dev → prod (mark as urgent)
4. Fast-track review
5. Merge and deploy
6. Later: PR prod → main

Note: Never push directly to prod or main.

================================================================================
                         ROLLBACK PROCESS
================================================================================

If deployment fails:

Option A: Revert commit
─────────────────────────────────────────────────────────────────────────────────
1. git revert <commit-sha>
2. Push to branch
3. Workflow runs with reverted code

Option B: Terraform state
─────────────────────────────────────────────────────────────────────────────────
1. Check previous state in S3 versioning
2. terraform plan to see drift
3. Fix configuration
4. terraform apply
