================================================================================
                         WORKFLOW PATTERNS
================================================================================

Standard Pattern (all workflows)
─────────────────────────────────────────────────────────────────────────────────
1. Trigger: push to branch OR workflow_dispatch (manual)
2. Runner: self-hosted Mac Mini (macOS, ARM64)
3. Auth: OIDC to AWS → Assume IAM Role
4. Secrets: Fetch from AWS Secrets Manager
5. Execute: Terraform init/plan/apply
6. Cleanup: Lock workflow variable back to 'true'

Flow Overview
─────────────────────────────────────────────────────────────────────────────────
Flow                                                              │ Type
──────────────────────────────────────────────────────────────────┼──────────
dev → Infrastructure-dev → dev AWS → dev Proxmox                  │ Infra
prod → Infrastructure-prod → prod AWS → prod Proxmox              │ Infra
dev-security → TerraformAdmin-dev → dev AWS (IAM)                 │ Security
prod-security → TerraformAdmin-prod → prod AWS (IAM)              │ Security
main → (no workflow, clean merges only)                           │ -

================================================================================
                         WORKFLOW LOCK MECHANISM
================================================================================

Why Locks Are Needed
─────────────────────────────────────────────────────────────────────────────────
├── workflow_dispatch (manual trigger) only works on default branch (main)
│   └── Cannot manually trigger workflows from dev/prod branches directly
│
└── Environment approval gates only available in GitHub Enterprise
    └── GitHub Pro does not support required reviewers for workflow runs

How It Works
─────────────────────────────────────────────────────────────────────────────────
├── LOCKED = 'true'  → Workflow skips execution (safe default)
├── LOCKED = 'false' → Workflow runs on push
└── workflow_dispatch always runs (manual override from main)

Implementation (add after runs-on)
─────────────────────────────────────────────────────────────────────────────────
```yaml
jobs:
  deploy:
    runs-on: macOS
    # Skip if locked (unless manual trigger)
    if: ${{ github.event_name == 'workflow_dispatch' || vars.WORKFLOW_NAME_LOCKED != 'true' }}
```

To Trigger a Workflow
─────────────────────────────────────────────────────────────────────────────────
1. Go to GitHub > Settings > Secrets and variables > Actions > Variables
2. Set *_LOCKED variable to 'false'
3. Push to branch (workflow runs)
4. Set variable back to 'true' (re-lock)

================================================================================
                         GOLDEN IMAGE WORKFLOW
================================================================================

Workflow: dev-proxmox-golden-image.yml

Purpose: Create Rocky Linux 10.1 VM template for cloning

Flow:
─────────────────────────────────────────────────────────────────────────────────
1. Terraform creates VM 9000 with ISO attached
2. Workflow polls VM status (waiting for manual OS install)
3. Manual: Install Rocky Linux, run setup script, shutdown VM
4. Workflow detects shutdown → converts to template
5. Template ready for cloning

Lock Variable: GOLDEN_IMAGE_DEV_LOCKED

================================================================================
                         TEST CLONES WORKFLOW
================================================================================

Workflow: dev-proxmox-test-clones.yml

Purpose: Verify golden image template works with cloud-init

Flow:
─────────────────────────────────────────────────────────────────────────────────
1. Clone 2 test VMs from template (different VLANs)
2. Apply cloud-init (hostname, network, root password)
3. Wait for VMs to boot and shutdown
4. Verify: hostname, network, cloud-init logs
5. Destroy test VMs (cleanup)

Lock Variable: TEST_CLONES_DEV_LOCKED

================================================================================
                         INFRASTRUCTURE WORKFLOW (Template)
================================================================================

Workflow: infrastructure-{env}.yml

Purpose: Deploy Proxmox infrastructure (VMs, LXCs)

Flow:
─────────────────────────────────────────────────────────────────────────────────
1. OIDC authenticate to AWS
2. Assume GitHubActions-Infrastructure-{env} role
3. Fetch Proxmox token from Secrets Manager
4. Terraform init with S3 backend
5. Terraform plan
6. Terraform apply
7. Output deployed resources

AWS Role: GitHubActions-Infrastructure-{env}
State Path: {env}/proxmox/*

================================================================================
                         SAMPLE WORKFLOW STRUCTURE
================================================================================

```yaml
name: Dev - Infrastructure

on:
  push:
    branches: [dev]
    paths:
      - 'terraform/dev/proxmox/**'
      - '.github/workflows/dev-infrastructure.yml'
  workflow_dispatch:

permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    runs-on: macOS
    if: ${{ github.event_name == 'workflow_dispatch' || vars.INFRA_DEV_LOCKED != 'true' }}

    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_ACCOUNT_ID_DEV }}:role/GitHubActions-Infrastructure-dev
          aws-region: ${{ vars.AWS_REGION }}

      - name: Get Proxmox Token
        run: |
          SECRET=$(aws secretsmanager get-secret-value --secret-id dev/proxmox/terraform-token --query SecretString --output text)
          echo "PROXMOX_VE_API_TOKEN=$(echo $SECRET | jq -r '.token_id')=$(echo $SECRET | jq -r '.token_secret')" >> $GITHUB_ENV

      - name: Terraform Init
        working-directory: terraform/dev/proxmox
        run: terraform init

      - name: Terraform Apply
        working-directory: terraform/dev/proxmox
        run: terraform apply -auto-approve
```
