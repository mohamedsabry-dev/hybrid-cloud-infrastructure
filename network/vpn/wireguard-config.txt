================================================================================
                         WIREGUARD VPN CONFIGURATION
================================================================================

Type: Site-to-Site VPN (Home to AWS)
Protocol: WireGuard (UDP)
Environments: Dev + Prod (separate tunnels)
On-prem endpoint: MikroTik L009UiGS-RM

================================================================================
                         TUNNEL SUMMARY
================================================================================

  Environment | On-Prem Tunnel | AWS Tunnel    | On-Prem Port | AWS Port
  ------------|----------------|---------------|--------------|----------
  Dev         | 172.16.200.1   | 172.16.200.2  | 51820        | 51820
  Prod        | 172.17.200.1   | 172.17.200.2  | 51830        | 51820

Tunnel IPs are within AWS VPC CIDR to simplify AllowedIPs routing.
Dev: 172.16.0.0/16, Prod: 172.17.0.0/16

================================================================================
                         AWS EC2 CONFIGURATION
================================================================================

Config File: /etc/wireguard/wg0.conf

DEV (wg-dev):
   [Interface]
   Address = 172.16.200.2/16
   ListenPort = 51820
   PrivateKey = <AWS_PRIVATE_KEY>
   PostUp = iptables forwarding + NAT masquerade
   PostDown = cleanup rules

   [Peer]
   PublicKey = <ON_PREM_DEV_PUBLIC_KEY>
   AllowedIPs = 172.16.200.1/32, 10.0.60.0/24, 10.0.61.0/24, 10.0.62.0/24,
                10.0.63.0/24, 10.0.64.0/24, 10.0.65.0/24, 10.0.5.0/24

PROD (wg-prod):
   [Interface]
   Address = 172.17.200.2/16
   ListenPort = 51820
   PrivateKey = <AWS_PRIVATE_KEY>
   PostUp = iptables forwarding + NAT masquerade
   PostDown = cleanup rules

   [Peer]
   PublicKey = <ON_PREM_PROD_PUBLIC_KEY>
   AllowedIPs = 172.17.200.1/32, 10.0.50.0/24, 10.0.51.0/24, 10.0.52.0/24,
                10.0.53.0/24, 10.0.54.0/24, 10.0.55.0/24, 10.0.5.0/24

================================================================================
                         VPN ACL (Environment Segmentation)
================================================================================

VPN traffic is segmented by environment on the MikroTik firewall:
  Dev VPN  (172.16.x.x) -> Dev VLANs (60-65) only
  Prod VPN (172.17.x.x) -> Prod VLANs (50-55) only

Cross-environment VPN traffic is blocked.

================================================================================
                         QUICK COMMANDS
================================================================================

   # Check tunnel status (AWS)
   sudo wg show

   # Restart WireGuard (AWS)
   sudo systemctl restart wg-quick@wg0

   # Check keepalive service (AWS)
   sudo systemctl status wg-keepalive

   # Test connectivity
   ping 172.16.200.1   # Dev tunnel
   ping 172.17.200.1   # Prod tunnel

================================================================================
                         TROUBLESHOOTING
================================================================================

ISP/CGNAT PORT BLOCKING:
  Symptom: One tunnel works, other doesn't. AWS tcpdump shows bidirectional
           packets, but on-prem shows RX: 0 bytes, no handshake.
  Cause:   ISP CGNAT silently blocks specific UDP ports.
  Fix:     Change on-prem listen port (e.g., 51820 -> 51830).
           AWS responds to source port, no change needed there.
  History: Prod port was 51820, blocked by ISP. Changed to 51830 (March 2026).
           Full investigation in TS-NET-004.
