================================================================================
                         !! READ FIRST !! STATE OF THIS FILE
================================================================================

This file documents the ORIGINAL switch design, where the FS308GP carried
BOTH the service VLAN trunks (Ports 2-5) AND the storage VLAN (Ports 6-8).

THAT IS NO LONGER THE CURRENT WIRING.

After the investigation in
  /troubleshooting/network/3-svc-network-instability-investigation.md
(TS-NET-003) found the real root cause — USB-ethernet adapter instability
on the Proxmox servers, not the switch or the router — I simplified the
wiring:

  - Each Proxmox server's svc0 now connects DIRECTLY to a router port
    (bypassing the switch entirely for service VLANs).
  - The FS308GP keeps only the storage VLAN (VLAN 40) role.
  - Switch ports 2-5 are unused.

I am keeping the sections below because the original design was useful
reference material and someone reading this (including future-me) should
be able to see what the "full" switch-based VLAN layout looked like. Think
of the Port Assignments, VLAN Networks, and Port Profiles sections as the
HISTORICAL design. The summary right below this block is what is actually
deployed TODAY.

Also note: references to "ER605 Port 4 / Port 5" in the historical port
table are the OLD on-prem router. That router has since been replaced by a
MikroTik L009UiGS-RM — see /network/README.md for the full story.

================================================================================
                         5. CLI CONFIG REFERENCE   [HISTORICAL
                                                    for the Port2/Port3 trunks]
================================================================================

   Exported from: network/backups/switchCfg.cfg

   # VLANs
   vlan 40                    # Storage
   vlan 50-55                 # Prod Services
   vlan 60-65                 # Dev Services
   vlan 99                    # Dump/Isolation

   # Management Interface
   interface vlan 1
     ip address 192.168.100.185 255.255.255.0 gateway 192.168.100.1

   # Example Trunk Port (Port2 - Prod)
   interface gigabitEthernet 1/0/2
     switchport general allowed vlan 99 untagged
     switchport general allowed vlan 50-55 tagged
     switchport pvid 99
     no switchport general allowed vlan 1
     power inline supply disable

   # Example Trunk Port (Port3 - Dev)
   interface gigabitEthernet 1/0/3
     switchport general allowed vlan 99 untagged
     switchport general allowed vlan 60-65 tagged
     switchport pvid 99
     no switchport general allowed vlan 1
     power inline supply disable

   # Example Storage Port (Port6)
   interface gigabitEthernet 1/0/6
     switchport general allowed vlan 99 untagged
     switchport general allowed vlan 40 tagged
     switchport pvid 99
     loopback-detection config process-mode port-based recovery-mode auto
     loopback-detection

================================================================================
                         6. ACL (Future)
================================================================================

   STATUS: Not configured yet.

   NOTE: the original plan here was switch-level ACLs to block inter-VLAN
   traffic as a defense-in-depth layer alongside the ER605 firewall. Two
   things have changed since that plan was written:

     1. The switch no longer carries the service VLANs at all (the whole
        point of the post-TS-NET-003 simplification). So inter-VLAN traffic
        between service VLANs never even touches this switch anymore — it
        is all enforced one hop up, at the router.
     2. The router is now MikroTik, not ER605 — which gives me a much
        richer firewall-rules surface to do this kind of enforcement
        cleanly at the router layer rather than pushing it down to the
        switch.

   So "switch-level ACLs for service VLAN isolation" is effectively no
   longer a goal. What is still potentially useful on the FS308GP:
     ├── Restrict management access (to the switch itself) to specific IPs
     └── Storage VLAN hardening if ever needed (currently overkill for a
         single-NAS setup)
