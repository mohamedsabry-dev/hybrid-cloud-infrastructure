================================================================================
                         NETWORK TOPOLOGY
================================================================================

COMPONENTS:
  1. ISP ONT                 - Internet gateway (fiber terminal)
  2. MikroTik L009UiGS-RM    - Firewall, VPN, Gateway, Router
                               (replaced a TP-Link ER605 — see network/README.md)
  3. FS308GP                 - L2 Switch, PoE, VLAN switching (storage only now)
  4. AX3000                  - Home WiFi Access Point (home devices only, not lab)
  5. AC750                   - Lab Management WiFi Access Point
  6. NAS FS6706T             - ASUSTOR FlashStor NFS Storage
  7. Prod Server             - Proxmox Production host (+ VMs / LXCs)
  8. Dev Server              - Proxmox Development host (+ VMs / LXCs)

================================================================================
                         TRAFFIC FLOW
================================================================================

Lab Traffic:
 └── All lab service-VLAN traffic routes through MikroTik for firewall / ACL
     control (dev→prod isolation, env→AWS VPN, etc.)

Home Traffic:
 └── Home devices on AX3000 WiFi go directly to ISP (isolated from lab)

Storage Traffic:
 └── VLAN 40 is L2-isolated on the FS308GP switch — NO router hop.
     Proxmox hosts and k8s worker VMs talk to the NAS directly over L2
     on VLAN 40. This was intentional from day one and has stayed the same
     across both the ER605 era and the MikroTik era.

================================================================================
                         VLAN SUMMARY
================================================================================

  VLAN 5      │ Management      │ Mgmt plane on MikroTik + Lab WiFi (AC750)
  VLAN 40     │ Storage         │ Switch-isolated; NAS, Proxmox stor0, k8s workers
  VLAN 50-55  │ Prod Services   │ Production workloads (trunked via MikroTik)
  VLAN 60-65  │ Dev Services    │ Development workloads (trunked via MikroTik)
  VLAN 99     │ Dump / Isolation│ Native PVID on trunk ports (unused traffic)

================================================================================
                         HISTORICAL NOTE
================================================================================

Two things have changed since the original topology was laid out:

  1. Router. Originally a TP-Link ER605 (Port 3 = AC750 AP, Port 4 = Dev
     SVC uplink to switch, Port 5 = Prod SVC uplink to switch). Replaced
     by the MikroTik L009UiGS-RM after a stack of VPN and debug-tooling
     issues documented in TS-NET-003 / 004 / 005.

  2. Service-VLAN path. Originally service VLANs (50-55 and 60-65) ran
     from the Proxmox servers through the FS308GP switch, then out to the
     router. After TS-NET-003 revealed the real root cause of the Dev
     network flapping was the Proxmox USB-ethernet adapter (NOT a router
     port or the switch, though both had been suspected at different
     phases), I rewired the service trunks to go DIRECTLY from each
     Proxmox host's svc0 to a dedicated router port. The FS308GP is kept,
     but only for the storage VLAN now.

Both the old ER605 config and the original "service VLAN through the
switch" setup are documented in the retired sections of the relevant
per-device files — see router/er605/README.md and the HISTORICAL parts
of switch/fs308gp/config.txt.
