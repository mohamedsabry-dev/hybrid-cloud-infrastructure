================================================================================
                         WIREGUARD VPN CONFIGURATION
================================================================================

Type: Site-to-Site VPN (Home to AWS)
Protocol: WireGuard (UDP)
Environments: Dev + Prod (separate tunnels)

================================================================================
                         1. TUNNEL SUMMARY
================================================================================

   +-------------+----------------+----------------+-------------+-------------+
   | Environment | ER605 Tunnel   | AWS Tunnel     | ER605 Port  | AWS Port    |
   +-------------+----------------+----------------+-------------+-------------+
   | Dev         | 172.16.200.1   | 172.16.200.2   | 51820       | 51820       |
   | Prod        | 172.17.200.1   | 172.17.200.2   | 51821       | 51820       |
   +-------------+----------------+----------------+-------------+-------------+

   NOTE: Tunnel IPs are within AWS VPC CIDR to solve ER605 AllowedIPs limitation.
         Dev: 172.16.0.0/16, Prod: 172.17.0.0/16

================================================================================
                         3. AWS EC2 CONFIGURATION
================================================================================

Config File: /etc/wireguard/wg0.conf

DEV (/etc/wireguard/wg0.conf on wg-dev):
   [Interface]
   Address = 172.16.200.2/16
   ListenPort = 51820
   PrivateKey = <AWS_PRIVATE_KEY>
   PostUp = iptables forwarding + NAT masquerade
   PostDown = cleanup rules

   [Peer]
   PublicKey = <ER605_DEV_PUBLIC_KEY>
   AllowedIPs = 172.16.200.1/32, 10.0.60.0/24, 10.0.61.0/24, 10.0.62.0/24,
                10.0.63.0/24, 10.0.64.0/24, 10.0.65.0/24, 10.0.5.0/24

PROD (/etc/wireguard/wg0.conf on wg-prod):
   [Interface]
   Address = 172.17.200.2/16
   ListenPort = 51820
   PrivateKey = <AWS_PRIVATE_KEY>
   PostUp = iptables forwarding + NAT masquerade
   PostDown = cleanup rules

   [Peer]
   PublicKey = <ER605_PROD_PUBLIC_KEY>
   AllowedIPs = 172.17.200.1/32, 10.0.50.0/24, 10.0.51.0/24, 10.0.52.0/24,
                10.0.53.0/24, 10.0.54.0/24, 10.0.55.0/24, 10.0.5.0/24

================================================================================
                         4. VPN ACL (Environment Segmentation)
================================================================================

Path: Firewall > Access Control

IP GROUPS:
   +----+------------------+--------------------------------------------------+
   | ID | Name             | Members                                          |
   +----+------------------+--------------------------------------------------+
   | 12 | vpn_prod         | AWS_PROD_Subnet (172.17.0.0/16)                  |
   | 13 | vpn_dev          | AWS_DEV_Subnet (172.16.0.0/16)                   |
   | 14 | Production_Env   | Prod VLANs (50-55) + Prod_Mgmt_IP                |
   | 15 | Development_Env  | Dev VLANs (60-65) + Dev_Mgmt_IP                  |
   +----+------------------+--------------------------------------------------+

ACL RULES:
   +----+----------+--------+-----------+-----------------+---------------------+
   | ID | Name     | Action | Source    | Destination     | Purpose             |
   +----+----------+--------+-----------+-----------------+---------------------+
   | 7  | vpn_dev  | Allow  | vpn_dev   | Development_Env | Dev VPN -> Dev only |
   | 8  | vpn_prod | Allow  | vpn_prod  | Production_Env  | Prod VPN -> Prod    |
   +----+----------+--------+-----------+-----------------+---------------------+

   NOTE: VPN traffic is segmented by environment.
         Dev VPN (172.16.x.x) can only reach Dev VLANs (60-65).
         Prod VPN (172.17.x.x) can only reach Prod VLANs (50-55).


================================================================================
                         5. QUICK COMMANDS
================================================================================

   # Check tunnel status (AWS)
   sudo wg show

   # Restart WireGuard (AWS)
   sudo systemctl restart wg-quick@wg0

   # Check keepalive service (AWS)
   sudo systemctl status wg-keepalive

   # Test connectivity
   ping 172.16.200.1   # Dev tunnel
   ping 172.17.200.1   # Prod tunnel
