================================================================================
                         RUNNER INSTALLATION
================================================================================

Step 1: Install Dependencies
─────────────────────────────────────────────────────────────────────────────────
# Install Homebrew (if not installed)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install required tools
brew install python@3.14 node terraform ansible awscli
brew install --cask docker powershell

Step 2: Download and Install GitHub Actions Runner
─────────────────────────────────────────────────────────────────────────────────
# Create runner directory
mkdir -p ~/WorkSpace/actions-runner && cd ~/WorkSpace/actions-runner

# Download latest runner (ARM64)
curl -o actions-runner-osx-arm64.tar.gz -L \
  https://github.com/actions/runner/releases/download/v2.331.0/actions-runner-osx-arm64-2.331.0.tar.gz

# Extract
tar xzf ./actions-runner-osx-arm64.tar.gz

Step 3: Configure Runner with Repository Token
─────────────────────────────────────────────────────────────────────────────────
# Get token from: GitHub Repo > Settings > Actions > Runners > New self-hosted runner

# Configure runner with labels
./config.sh --url https://github.com/mohamedsabry-dev/hybrid-cloud-infrastructure \
  --token YOUR_RUNNER_TOKEN \
  --labels self-hosted,macOS,ARM64 \
  --name Mohameds-Mac-mini

Step 4: Setup Runner as Auto-Start Service (launchd)
─────────────────────────────────────────────────────────────────────────────────
# Install as service
sudo ./svc.sh install

# Start the service
sudo ./svc.sh start

# Check status
sudo ./svc.sh status

Workflow Lock Pattern (Safe Trigger Mechanism)
─────────────────────────────────────────────────────────────────────────────────
The *_LOCKED variables provide a safe trigger mechanism as a workaround for:

├── workflow_dispatch (manual trigger) only works on default branch (main)
│   └── Cannot manually trigger workflows from dev/prod branches directly
│
└── Environment approval gates only available in GitHub Enterprise
    └── GitHub Pro does not support required reviewers for workflow runs

How it works:
├── LOCKED = true  → Workflow skips execution (safe default)
├── LOCKED = false → Workflow runs on push
└── workflow_dispatch always runs (manual override)

Usage in workflow (after runs-on):
```yaml
jobs:
  deploy:
    runs-on: macOS
    # Skip if locked (unless manual trigger)
    if: ${{ github.event_name == 'workflow_dispatch' || vars.GOLDEN_IMAGE_DEV_LOCKED != 'true' }}
```

To trigger a workflow:
1. Set variable to 'false' in GitHub UI
2. Push to branch (workflow runs)
3. Set variable back to 'true' (re-lock)
