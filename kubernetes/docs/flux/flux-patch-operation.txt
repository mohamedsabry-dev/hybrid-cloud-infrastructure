# Flux Config Edit Guide
> How to safely modify Flux controller config without breaking things

---

## ❌ Never Edit This Directly
`flux-system/gotk-components.yaml`
- Generated by `flux bootstrap`
- Overwritten on every Flux upgrade
- Direct edits = lost changes

---

## ✅ The Clean Way: Patch Files

**Step 1** — Create a patch file next to kustomization.yaml:
```
flux-system/
├── gotk-components.yaml       ← never touch
├── gotk-sync.yaml             ← never touch
├── kustomization.yaml         ← reference your patch here
└── your-patch.yaml            ← your changes go here
```

**Step 2** — Reference it in `kustomization.yaml`:
```yaml
patches:
  - path: your-patch.yaml
    target:
      kind: Deployment
      labelSelector: app.kubernetes.io/part-of=flux
```

**Step 3** — Write only the fields you want to change:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: helm-controller
  namespace: flux-system
spec:
  replicas: 2
  template:
    spec:
      affinity:
        podAntiAffinity:
          ...
```
Kustomize merges this on top. Everything else stays untouched.

---

## 🔍 Before Editing — Inspect Current Config

**See live Deployment from cluster:**
```bash
kubectl get deployment helm-controller -n flux-system -o yaml
```

**List all Flux deployments:**
```bash
kubectl get deployments -n flux-system
```

**Search field in gotk-components.yaml in repo:**
```bash
grep -A 50 "name: helm-controller" flux-system/gotk-components.yaml
```

---

## 🔄 How Changes Get Applied

```
You push patch to Git
   → Flux detects change (every 1 min)
   → Kustomize loads gotk-components.yaml
   → Merges your patch on top
   → Sends final manifest to Kubernetes
   → Controllers restart with new config
```

---

## 💡 Key Rules
- Patch = modify existing resource, never create new
- Only write fields you want to change, not the full manifest
- Patch survives `flux bootstrap` upgrades, direct edits do not
- Use `kubectl get ... -o yaml` to discover available fields
