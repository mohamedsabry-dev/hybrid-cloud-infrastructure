# Flux — dev

Flux GitOps controllers and sync Kustomizations for the dev cluster. Watches the `dev` branch at path `./kubernetes/dev/flux` (see `flux-system/gotk-sync.yaml`).

## Layout

| File | Purpose |
|------|---------|
| `flux-system/gotk-components.yaml` | Flux controllers (generated by `flux bootstrap` — never edit directly) |
| `flux-system/gotk-sync.yaml` | GitRepository + root Kustomization (generated — pins branch + watched path) |
| `flux-system/flux-pod-anti-affinity.yaml` | Patch: preferred pod anti-affinity across nodes for all 4 controllers |
| `flux-system/kustomization.yaml` | Stitches components + sync + anti-affinity patch |
| `infrastructure-sync.yaml` | Flux Kustomization → `deployments/infrastructure/` (has healthCheck on vault-agent-injector) |
| `apps-sync.yaml` | Flux Kustomization → `deployments/apps/` (dependsOn: infrastructure, prune: true) |
| `kustomization.yaml` | Top-level — includes flux-system + both sync Kustomizations |

## Quick commands

```bash
flux get sources git                   # GitRepository status
flux get kustomizations                # all Kustomization status + Ready condition
flux reconcile source git flux-system  # force git re-pull (bypass 1m poll)
flux reconcile kustomization infrastructure
flux reconcile kustomization apps
flux suspend kustomization --all       # emergency stop (see TS-K8S-042)
flux resume kustomization --all
flux logs --level=error --all-namespaces
```

## Why it's shaped this way

The reasoning — infra/apps split, healthCheck on vault-agent-injector, anti-affinity patch, no priorityClass, branch pinning, what Flux doesn't save you from — lives in [`DESIGN.md`](DESIGN.md). The story came out of TS-K8S-012, TS-K8S-019, and TS-K8S-042.

## Prod mirror

[`../../prod/flux/`](../../prod/flux/) is an identical mirror — only `gotk-sync.yaml` (`branch: prod`, `path: ./kubernetes/prod/flux`) and the `path:` in the two sync files differ. Prod has its own copy of DESIGN.md with the same reasoning.
