================================================================================
VEEAM EMERGENCY BACKUP USER SETUP - COMPLETE PROCEDURE
================================================================================

OVERVIEW
--------
This procedure creates a secure SSH key-based authentication for Veeam backups.
The SSH keys are stored in HashiCorp Vault (not hardcoded in playbooks) and
deployed via Ansible to Linux servers.


================================================================================
PHASE 1: SSH KEY GENERATION (Windows Veeam Server)
================================================================================

1. Generate SSH Key Pair
   ssh-keygen -t ed25519 -C "veeam_emergency_key"

2. Copy the Public Key
   In PowerShell:
   Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub

3. Backup Private Key
   - Copy the private key from C:\Users\YourUser\.ssh\id_ed25519
   - Store it securely on a password-protected USB or secure vault
   - This is your emergency backup before deletion


================================================================================
PHASE 2: VAULT SETUP AND KEY STORAGE (Linux/Ansible Node)
================================================================================

2.1 - Install Prerequisites
-----------------------------
# Install Python library for Vault
pip3 install hvac

# Install Ansible Collection for Vault
ansible-galaxy collection install community.hashi_vault


2.2 - Store Public Key in Vault
---------------------------------
# Login to Vault
export VAULT_ADDR='http://127.0.0.1:8200'
vault login -method=userpass username=admin1

# Store the public key
# Replace "ssh-ed25519 AAA..." with your ACTUAL copied public key from Windows
vault kv put secret/infra/veeam_emergency \
    public_key="ssh-ed25519 AAAAC3Nz...... veeam_emergency_key"


2.3 - Store Private Key in Vault (SECURE METHOD)
--------------------------------------------------
IMPORTANT: DO NOT paste the private key directly into the command line!

Why?
- Multiline keys break in terminal (-----BEGIN... lines cause errors)
- Keys may be saved to shell history even with HISTCONTROL=ignorespace

CORRECT METHOD (Using @ symbol):

1. Create temporary file:
   nano temp_key.txt
   # Paste your private key from Windows
   # Save and exit (Ctrl+O, Enter, Ctrl+X)

2. Patch Vault using file:
   vault kv patch secret/infra/veeam_emergency private_key=@temp_key.txt

3. Securely delete the file:
   shred -u temp_key.txt


================================================================================
PHASE 3: CONFIGURE ANSIBLE PLAYBOOK
================================================================================

Add Vault lookup in your playbook/vars file:

# Format: lookup('community.hashi_vault.hashi_vault', 'path', key='field', url='...')
# Replace '10.0.20.191' with your actual Vault server IP
veeam_public_key: "{{ lookup('community.hashi_vault.hashi_vault', 'secret/data/infra/veeam_emergency', key='public_key', url='http://10.0.20.191:8200') }}"


================================================================================
PHASE 4: RUN ANSIBLE PLAYBOOK
================================================================================

4.1 - Authenticate with Vault
-------------------------------
vault login -method=userpass username=admin1
# Copy the token from output


4.2 - Export Environment Variables
------------------------------------
# Set Vault address (The Map)
export VAULT_ADDR='http://10.0.20.191:8200'

# Set Vault token (The Key)
export VAULT_TOKEN='<YOUR_VAULT_TOKEN>'


4.3 - Execute Playbook
-----------------------
ansible-playbook -i ../inventory create_veeam_user.yml


4.4 - Cleanup Environment Variables
-------------------------------------
unset VAULT_TOKEN
unset VAULT_ADDR


================================================================================
PHASE 5: IMPORT KEY TO VEEAM (Windows Veeam Server)
================================================================================

5.1 - Open Credentials Manager
--------------------------------
1. Open Veeam Backup & Replication Console
2. Click Main Menu (≡ in top-left corner)
3. Hover over "Credentials" → Click "Manage credentials"


5.2 - Add Linux Private Key Credential
----------------------------------------
1. Click Add → Select "Linux private key"

2. Fill in the details:
   - Username: veeam_user
   - Password: (Leave Empty)
   - Private key: Select "From file"
   - File Path: C:\Users\YourUser\.ssh\id_ed25519
   - Passphrase: (Leave Empty)
   - Description: "Emergency Break-Glass (Key Based)"

3. Advanced Settings:
   - Check "Elevate account privileges automatically"
   - No root password needed (NOPASSWD configured via Ansible)

4. Click OK/Apply


================================================================================
PHASE 6: TESTING
================================================================================

6.1 - Test SSH Connection
---------------------------
1. Go to Inventory view (bottom-left menu)
2. Click Physical Infrastructure
3. Right-click a Linux VM (e.g., k8s-master) → Properties
4. Click Next until "Credentials" step
5. Select your new "veeam_user" credential
6. Click "Test Now" or "Apply"

Expected Results:
✅ Green check: "SSH connection established"
✅ Green check: "Root access verification"

❌ If failed:
- Verify Veeam Server IP is in 10.0.20.0/24 range
- Check if VMkernel has required services:
  * vSphere Replication
  * vSphere Replication NFC
  * vSphere Backup NFC
  * NVMe over TCP
  * NVMe over RDMA


6.2 - Confirm Credential Works
--------------------------------
After successful test, confirm the credential is working before cleanup.


================================================================================
PHASE 7: SECURE CLEANUP (Windows Veeam Server)
================================================================================

⚠️  ONLY perform cleanup AFTER Phase 6 is successful!

1. Backup Public Key
   - Save id_ed25519.pub to secure USB/vault (alongside private key backup)

2. Close Veeam application

3. Delete SSH keys from Windows:
   - Navigate to: C:\Users\YourUser\.ssh\
   - Delete: id_ed25519 (Private Key)
   - Delete: id_ed25519.pub (Public Key)

4. Empty Recycle Bin
